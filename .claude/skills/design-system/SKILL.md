# knittinglog 디자인 시스템 규약

> 구조는 [docs/REDESIGN.md](../../../docs/REDESIGN.md), 토큰과 톤은
> [docs/DESIGN.md](../../../docs/DESIGN.md). **이 문서는 "완성됐다"의 정의다.**

이 문서가 존재하는 이유는 하나다. 2026-08 시점의 앱을 측정했더니 이랬다.

| 항목                         | 전체 앱에서 |
| ---------------------------- | ----------- |
| `focus-visible:` 스타일      | **1곳**     |
| `active:` (누를 때 반응)     | 8곳         |
| `disabled:`                  | 4곳         |
| `@keyframes` · `animate-`    | **0**       |
| 로딩 상태 처리               | **0**       |
| 스켈레톤                     | **0**       |
| 데이터 대기 중 `return null` | **56곳**    |

기능은 다 있는데 **화면이 반응하지 않는다.** 눌러도 눌린 표시가 없고, 이동할
때마다 하얗게 번쩍이고, 아무것도 움직이지 않는다. 이게 "직접 만든 것 같다"의
정체이지 색이나 서체가 아니다.

---

## 1. 무엇도 이것 없이 끝나지 않는다

### 1.1 만질 수 있는 것은 일곱 상태를 갖는다

버튼·링크·입력·선택·탭·카드(누르는 것)·토글 — 전부.

| 상태            | 최소 요구                                                           |
| --------------- | ------------------------------------------------------------------- |
| `default`       | —                                                                   |
| `hover`         | 포인터 기기에서만. `@media (hover: hover)` 안에 둔다                |
| `focus-visible` | **2px 링 + 2px 오프셋.** 마우스 클릭에는 뜨지 않는다                |
| `active`        | 눌린 즉시 보이는 변화(축소 0.97 또는 명도). 터치 지연 없이          |
| `disabled`      | 불투명도 40% + `cursor: not-allowed` + 포인터 이벤트 유지(툴팁용)   |
| `loading`       | `aria-busy` + 라벨 자리를 유지한 스피너. **버튼 폭이 변하면 안 됨** |
| `error`         | 테두리 + 아이콘 + 글. 색만으로 알리지 않는다                        |

`hover`만 있는 컴포넌트는 미완성이다. 폰에는 hover가 없고, 이 앱의 사용자는
폰에 있다.

### 1.2 데이터를 읽는 화면은 네 화면을 갖는다

**`return null`은 금지다.** 지금 56곳이 그렇게 되어 있고, 그래서 화면을 옮길
때마다 흰 판이 한 번 지나간다. 사용자는 그걸 "느리다"가 아니라 "깨졌다"로 읽는다.

| 화면      | 규칙                                                                 |
| --------- | -------------------------------------------------------------------- |
| `loading` | **레이아웃이 같은 스켈레톤.** 로딩과 완료 사이에 화면이 튀면 안 된다 |
| `empty`   | 무엇을 얻게 되는지 + 그리로 가는 버튼 하나. "없어요"로 끝내지 않는다 |
| `error`   | 무엇이 실패했는지 + **다시 시도 버튼**. 사과문은 넣지 않는다         |
| `partial` | 일부만 있을 때(사진은 있고 게이지는 없음) 빈 자리를 접는다           |

한 화면에 빈 섹션이 셋 이상이면 그건 화면이 아니라 할 일 목록이다. 접어라.

### 1.3 모션은 세 가지만 쓴다

토큰은 `src/index.css`에 있고 **여기 없는 값을 새로 쓰지 않는다.**

| 이름          | 시간  | 이징                        | 쓰는 곳                    |
| ------------- | ----- | --------------------------- | -------------------------- |
| `--ease-tap`  | 90ms  | `cubic-bezier(.2,0,.4,1)`   | 눌림, 색 바뀜, 호버        |
| `--ease-move` | 220ms | `cubic-bezier(.22,1,.36,1)` | 시트·패널이 들어오고 나감  |
| `--ease-soft` | 320ms | `cubic-bezier(.4,0,.2,1)`   | 높이·목록 재배치, 스켈레톤 |

규칙:

- **`prefers-reduced-motion: reduce`에서 전부 0ms로 떨어진다.** 예외 없다.
- 위치·불투명도·`transform`만 애니메이션한다. `width`/`height`/`top`은
  레이아웃을 다시 계산해서 손이 끊긴다.
- **뜨기 모드의 `+1`에는 전환을 걸지 않는다.** 세는 동작은 즉시여야 하고,
  90ms도 100단을 세면 9초다. 대신 촉각(`haptic()`)이 응답을 맡는다.
- 장식 애니메이션은 없다. 움직이는 것은 전부 "무엇이 어디서 왔는지"를 말한다.

### 1.4 떠 있는 것에만 그림자

| 높이 | 대상                | 값                  |
| ---- | ------------------- | ------------------- |
| 0    | 카드·목록·입력      | 그림자 없음. 1px 선 |
| 1    | 붙어 있는 바·팝오버 | `--shadow-raised`   |
| 2    | 시트·다이얼로그     | `--shadow-overlay`  |
| 3    | 토스트              | `--shadow-overlay`  |

시트·다이얼로그는 **바탕을 덮고**(scrim), **포커스를 가두고**(focus trap),
**Esc로 닫히고**, 열릴 때 아래에서 올라온다. 셋 중 하나라도 없으면 시트가 아니라
그냥 떠 있는 div다.

## 2. 한국어 화면의 조판

- **`word-break: keep-all`이 기본이다.** 없으면 "회색 래글런 스웨터"가
  `회색 래글 / 런 스웨터`로 끊긴다. 실제로 그랬다.
- 제목에 `text-wrap: balance`.
- 숫자는 언제나 `font-variant-numeric: tabular-nums`. 단수가 흔들리면 안 된다.
- 한글에 음수 자간을 넉넉히 주지 않는다. 24px 이상에서만 최소한으로.
- 버튼 라벨은 `white-space: nowrap`. 두 글자 버튼이 세로로 쪼개지는 걸 막는다.

## 3. 접근성 — 통과 기준이지 권장이 아니다

- 모든 조작 가능한 것에 **눈에 보이는 `focus-visible`**. 키보드만으로 주요 흐름
  (프로젝트 만들기 → 카운터 만들기 → 세기)이 끝까지 가야 한다.
- 아이콘만 있는 버튼에 `aria-label` 필수.
- 상태를 색으로만 알리지 않는다(잠시멈춤·오류·경고 전부).
- 터치 타깃 44px. 뜨기 모드는 그보다 훨씬 크다.
- 본문 대비 4.5:1, 큰 글자 3:1. 회색 위 회색을 만들지 않는다.
- 화면 이동 시 제목으로 포커스를 옮긴다.

## 4. 화면을 짜는 순서

1. **로딩 화면을 먼저 그린다.** 완성 화면을 먼저 그리면 로딩은 영영 안 온다.
2. 빈 화면. 새 사용자가 보는 것이고 첫인상을 정한다.
3. 채워진 화면.
4. 실패 화면.
5. 극단값 — 제목 40자, 목록 200개, 사진 0장, 사진 50장.

## 5. 코드리뷰 체크리스트

UI를 건드린 변경은 이걸 통과해야 한다. **하나라도 "아니오"면 아직 안 끝났다.**

- [ ] 새로 만든 조작 요소에 `focus-visible`·`active`·`disabled`가 있다
- [ ] `return null`로 로딩을 때우지 않았다 — 스켈레톤이 있다
- [ ] 빈 상태에 다음 행동으로 가는 버튼이 하나 있다
- [ ] 실패했을 때 다시 시도할 수 있다
- [ ] `prefers-reduced-motion`에서 애니메이션이 멈춘다
- [ ] 키보드만으로 이 화면의 주 동작을 끝낼 수 있다
- [ ] 긴 한글 제목이 단어 중간에서 끊기지 않는다
- [ ] 폰(390px)과 PC(1280px) 양쪽에서 찍어봤다 (`scripts/shot.mjs`)
- [ ] 다크 모드에서 확인했다
- [ ] 토큰만 썼다 — 하드코딩된 색·간격·시간이 없다

## 6. 하지 말 것

- 토큰 밖의 색·간격·반경·시간을 파일 안에서 만들어 쓰기
- 목적 없는 모션 (튀는 것, 회전하는 것, 시선을 끌기만 하는 것)
- 한 화면에 두 가지 시각 비유 섞기 (둥근 카드 + 각진 표)
- 색만으로 상태 알리기
- hover에만 정보를 두기 — 폰에는 hover가 없다
- 스피너로 전체 화면 덮기 — 스켈레톤이 맥락을 지킨다
- 44px 아래 터치 타깃
