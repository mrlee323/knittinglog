# knittinglog — 화면 개편 계획

> 기능은 다 있는데 화면이 그걸 못 보여준다. 그걸 고치는 계획.

- 문서 상태: v0.1 (2026-08-29)
- 선행 문서: [PLAN.md](PLAN.md) §13(시각 우선 전환), [DESIGN.md](DESIGN.md)

---

## 1. 왜 이 문서가 필요한가

`PLAN.md` §13이 이미 같은 진단을 한 적이 있다 — "`P0`가 다 돌아가는데도 다른 앱에도
다 있는 기능으로 읽혔다." 그때의 처방은 **그림을 넣는 것**이었고(작품 사진·게이지
도식·문양 렌더러·천 미리보기), 그건 실제로 들어갔다.

그런데 화면은 여전히 좋아 보이지 않는다. 앱을 띄워서 주요 화면을 찍어보고 나서
원인이 달랐다는 걸 알았다. **문제는 그림의 부재가 아니라 화면의 구조다.**

이 문서는 화면을 실제로 확인한 뒤 쓴 것이고, 아래 진단은 전부 찍은 화면에서
나왔다. 재현 방법은 §6에 있다.

---

## 2. 먼저 짚어둘 것 — 디자인 시스템은 문제가 아니다

[DESIGN.md](DESIGN.md)를 의심하고 시작했지만, 확인해 보니 토큰은 지켜지고 있었다.

| 규칙           | 문서        | 실제                  |
| -------------- | ----------- | --------------------- |
| 입력·버튼 높이 | 44px        | `min-h-11` ✅         |
| 카드·입력 반경 | 6px         | `--radius-md: 6px` ✅ |
| 그림자         | 뜨는 것에만 | 카드에 그림자 없음 ✅ |
| 강조색         | 먹색        | `accent = #1b1a18` ✅ |

**"UI에서 색을 뺀다"는 방향도 옳다.** 뜨개는 색을 고르는 취미이고, 브랜드 색이
작품 사진·실 색과 경쟁하면 안 된다. 이건 지켜야 한다.

문제는 그 판단의 **대가를 치르지 않은 것**이다. 색으로 강약을 만들지 않기로 했으면
**크기·굵기·여백·밀도**가 그 일을 대신해야 하는데, 지금은 그것들도 균일하다.
그래서 모든 요소가 같은 목소리로 말하고, 결과적으로 아무것도 말하지 않는다.

**색을 뺀 화면은 정보 구조가 더 정확해야 한다.** 지금 부족한 건 그쪽이다.

## 3. 진단

### A. 제목이 단어 중간에서 끊긴다 — 그냥 결함

프로젝트 상세에서 "회색 래글런 스웨터"가 **"회색 래글 / 런 스웨터"** 로 나온다.
두 가지가 겹쳤다.

1. 공유 버튼이 제목과 같은 줄에 있어 제목이 쓸 수 있는 폭이 절반이다
2. 한글에 줄바꿈 규칙이 없다 — CSS 기본값은 아무 글자에서나 끊는다

**이미 답을 갖고 있다.** `domain/card.ts`의 `wrapText`가 공유 카드에서 CJK 금칙
처리를 한다. 카드는 남의 타임라인에 올라가니 신경 썼고, 정작 매일 보는 화면에는
없다. CSS `word-break: keep-all`이면 되는 일이다.

### B. 프로젝트 개요가 평평하다 — 가장 큰 문제

새 프로젝트 하나짜리 개요 화면이 폰에서 **3,664px**다. 섹션이 열한 개이고 전부
같은 무게로 세로로 쌓인다.

```
다음은 이걸 하면 돼요 → 최근 기록 → 참고 자료 → 기법·종류 → [뜨기 시작]
→ 조각 → 카운터 → 게이지 → 쓰는 실 → 쓰는 바늘 → 이대로 다시 뜨기 → 수정·삭제
```

**이 앱에서 가장 자주 누를 버튼이 화면 중간에 파묻혀 있다.** DESIGN.md는 "개요
진행 카드의 큰 버튼을 뜨기 모드의 유일한 문으로 삼았다"고 적었는데, 그 문이
목록의 다섯 번째 항목이다. 목록의 다섯 번째는 문이 아니라 항목이다.

### C. 빈 상태가 화면을 지배한다

방금 만든 프로젝트를 열면 화면에 이렇게 적혀 있다.

> 사진이 없어요 · 아직 올려둔 자료가 없어요 · 아직 조각이 없어요 ·
> 기록한 스와치가 없어요 · 카운터…

**첫인상이 결핍 목록이다.** 각 문구는 하나씩 보면 친절한데, 다섯 개가 세로로
쌓이면 "이 앱은 내가 채워야 할 게 많다"는 메시지가 된다. 이 앱의 전제는
"중단해도 괜찮다"인데 시작하자마자 숙제를 준다.

### D. 방금 만든 프로젝트가 홈에 없다

프로젝트를 만들면 상태가 `계획중`이다. 그런데 홈의 카드는 `진행중`·`잠시멈춤`·
`완성` 셋뿐이라, 만들자마자 홈으로 가면 **"지금 뜨고 있는 게 없어요"** 가 뜬다.
방금 만든 것이 어디에도 없다.

첫 사용에서 이건 "저장이 안 됐나?"로 읽힌다.

### E. 뜨기 모드에서 도안이 없으면 화면 절반이 안내문

폰 세로에서 위쪽 40%가 "작업대에 도안이나 참고 자료를 올려두면 뜨면서 볼 수
있어요" **한 줄**이다. 그 대가로 단수 숫자가 화면 높이의 12%로 눌려 있다.

DESIGN.md는 "뜨기 모드의 +1 영역은 화면 절반"이라고 적었는데, 도안이 없는
상태에서는 그 절반을 안내문이 가져간다. 그리고 대부분의 프로젝트는 도안을
올리지 않은 상태다.

+1 영역도 문제다. **회색 빈 상자에 얇은 테두리**라서 눌리는 곳이 아니라 "여기
뭔가 빠졌다"로 보인다.

### F. 넓은 화면은 여백만 는다

DESIGN.md는 **"기준 화면은 태블릿과 PC"** 라고 선언했다. 그런데 1280px에서
프로젝트 목록은 한 열이고 카드 폭이 500px이며 오른쪽 700px이 비어 있다.
홈은 본문 열이 통째로 비고 데이터는 좁은 오른쪽 열에만 있다.

지금 넓은 화면 레이아웃은 **폰 레이아웃을 가운데 정렬한 것**이다. 기준 화면이라고
적어둔 곳에서 그렇다.

### G. 강약이 없다

타이포 스케일이 여덟 단계인데 실제 화면은 `body`·`small`·`caption` 세 개에 몰려
있다. `display`·`title`은 화면 제목에만 쓰이고, 정작 **중요한 숫자**(단수·남은 단·
실 잔량)가 본문과 같은 크기다.

DESIGN.md 원칙 3은 "숫자가 가장 또렷해야 한다"이다. 지금은 아니다.

## 4. 무엇을 바꾸나 — 원칙 셋

**1. 화면마다 주인공이 하나다.**
개요의 주인공은 "지금 어디까지 왔고, 이어 뜨려면 여기를 눌러라"이다. 나머지는
전부 조연이고, 조연은 조연처럼 작아야 한다.

**2. 비어 있으면 접는다.**
없는 것을 다섯 줄로 알리지 않는다. 비어 있는 섹션은 접고, 채우는 길은 한 자리에
모은다. 화면은 **가진 것**을 보여주는 곳이다.

**3. 색을 안 쓰기로 했으면 크기로 말한다.**
같은 무채색 안에서 위계를 만드는 수단은 크기·굵기·여백·정렬뿐이다. 지금은 그것을
쓰지 않고 있으므로, 쓰기 시작한다.

## 5. 단계

### 0단계 — 결함 (반나절)

개편과 무관하게 그냥 틀린 것들이다.

- 제목 `word-break: keep-all` + 공유 버튼을 제목 줄에서 분리 (§3-A)
- 홈에 `계획중` 프로젝트가 보이게 한다 (§3-D)
- 뜨기 모드: 도안이 없으면 카운터가 화면 전체를 쓴다 (§3-E)

### 1단계 — 프로젝트 개요 재구성 ★ 가장 값어치 있음

이 앱에서 가장 자주 여는 화면이고, 지금 가장 나쁜 화면이다.

- **맨 위 한 덩어리**: 대표 사진 + 진행도 + 큰 `뜨기` 버튼. 이것만 화면에 꽉 찬다.
- 나머지 섹션(조각·카운터·게이지·실·바늘)은 **비어 있으면 접는다.** 채우는 길은
  섹션마다 흩어진 `+` 대신 한 자리로 모은다.
- `수정`·`삭제`·`이대로 다시 뜨기`는 본문에서 빼고 상단 메뉴로.
- 시작 안내(`start-guide`)는 이미 있으니, 그걸 빈 프로젝트의 **유일한** 카드로 둔다.
  "없어요" 다섯 줄을 이것 하나가 대신한다.

### 2단계 — 위계와 밀도

- 타이포 스케일을 실제로 쓴다. 특히 **숫자**(단수·잔량·게이지)를 한 단계 올린다.
- 섹션 제목 `heading` / 카드 제목 `subhead` / 보조 `caption` 을 화면에서 검사한다.
- 섹션 사이 32, 내부 12로 여백을 정리한다. 지금은 둘 다 20~24라 구분이 안 된다.

### 3단계 — 넓은 화면

"기준 화면은 태블릿과 PC"라는 선언을 실제로 지킨다.

- 프로젝트·실·게이지 목록을 **격자**로 (`md` 2열, `xl` 3열)
- 홈의 두 단 비율을 뒤집는다 — 지금은 데이터가 좁은 쪽에 있다
- 개요의 두 단(보는 것 / 조작하는 것)을 실제로 켠다

### 4단계 — 뜨기 모드

- 단수 숫자를 화면 높이 기준으로 키운다 (지금 12% → 25% 이상)
- `+1` 영역을 **채운다.** 빈 상자에 테두리가 아니라 눌리는 면으로 보이게
- "라이프라인 없음"처럼 **없다는 정보**를 눈에 띄게 두지 않는다
- 목표 단수가 없으면 진행률 자리를 비우지 말고 세션 정보로 채운다

### 5단계 — 인상 (선택, 나중)

여기까지 하고도 마음에 안 들면 그때가 **방향 자체를 바꿀지** 정하는 자리다.
지금은 아니다. 구조가 틀린 상태에서 스타일을 바꾸면 틀린 구조가 다른 옷을 입을 뿐이다.

## 6. 확인 방법

주관으로 판정하지 않는다. 화면을 찍어서 본다.

```
npm run dev
npx --yes playwright@latest install chromium          # 처음 한 번
npx --yes -p playwright@latest node scripts/shot.mjs  # 폰·PC 두 폭으로 캡처
```

playwright를 의존성에 넣지 않은 것은 의도다 — 런타임에 쓰지 않는 것을 번들 옆에
두지 않는다. 결과는 `.shots/`에 떨어지고 git에는 올리지 않는다.

단계마다 같은 화면을 같은 조건으로 찍어 이전과 나란히 둔다. "좋아졌다"가 아니라
**무엇이 어떻게 달라졌는지** 보이게 한다.

측정할 수 있는 것 몇 가지를 기준으로 둔다.

| 기준                                 | 지금       | 목표         |
| ------------------------------------ | ---------- | ------------ |
| 프로젝트 개요 높이 (폰, 빈 프로젝트) | 3,664px    | 1,200px 이하 |
| `뜨기` 버튼까지의 스크롤             | 약 800px   | 0 (첫 화면)  |
| 뜨기 모드 단수 숫자 높이             | 화면의 12% | 25% 이상     |
| 1280px에서 죽은 가로 여백            | 약 700px   | 200px 이하   |

## 7. 하지 않을 것

- **디자인 시스템을 갈아엎지 않는다.** §2에서 봤듯 토큰은 지켜지고 있고 방향도
  옳다. 문제는 정보 구조다.
- **무채색 원칙을 버리지 않는다.** 색을 넣으면 당장 화려해 보이지만, 작품 사진과
  실 색이 죽는다. 이 앱이 보여줘야 하는 건 UI가 아니라 사용자의 뜨개다.
- **외부 스타일 스킬(TypeUI 등)을 지금 붙이지 않는다.** 그건 "무슨 톤으로 보일까"의
  답이고, 지금 틀린 건 "무엇을 먼저 보여줄까"다. 5단계에서 다시 본다.
- **새 기능을 이 개편에 섞지 않는다.** 기능 추가는 별도 문서에서 다룬다.
