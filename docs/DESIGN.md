# knittinglog — 디자인 시스템

- 문서 상태: v1 (2026-08-14)
- 방향: **스와치(Swatch)** — UI에서 색을 빼고, 사진과 실이 화면의 유일한 색이 된다
- 레퍼런스: Notion(작은 반경 · 헤어라인 구분선 · 무채색 크롬), velog(한글 본문 조판)

---

## 1. 원칙

**1. UI는 색을 갖지 않는다.**
뜨개는 색을 고르는 취미다. 브랜드 색이 화면에 있으면 작품 사진과 실 색이 그것과 경쟁한다.
그래서 강조색(accent)을 별도 색상으로 두지 않고 **먹색(ink) 자체**로 쓴다.
화면에서 채도를 가진 것은 사진, 실 색, 그리고 최소한의 상태 표시뿐이다.

**2. 구분은 그림자가 아니라 선으로 한다.**
1px 헤어라인이 기본 분리 수단이다. 그림자는 화면 위에 뜨는 것(시트·다이얼로그)에만 쓴다.
카드가 떠 있을 이유가 없다.

**3. 숫자가 가장 또렷해야 한다.**
단수·코수·게이지가 이 서비스의 핵심 정보다. 숫자에는 항상 고정폭(tabular) 자형을 쓰고,
정렬되는 자리(목록·표·카운터)에서 자릿수가 흔들리지 않게 한다.

**4. 뜨는 중 화면은 다른 규칙을 따른다.**
관리 화면이 조용한 문서라면 뜨기 모드는 도구다. 큰 터치 타깃, 최소 정보, 높은 대비,
한 손 조작. 이 문서의 여백·크기 규칙이 거기서는 적용되지 않는다.

---

## 2. 색

### 뉴트럴

무채색이 아니라 **아주 약하게 따뜻한 회색**이다(채도 4~8%). 순수 회색은 선택하지 않은 것처럼
보이고, 크림색으로 넘어가면 흔한 "따뜻한 공예" 톤이 된다. 그 사이에 둔다.

| 토큰          | 라이트    | 다크      | 용도                       |
| ------------- | --------- | --------- | -------------------------- |
| `canvas`      | `#fbfaf9` | `#171615` | 페이지 바탕                |
| `surface`     | `#ffffff` | `#1e1d1c` | 카드·시트                  |
| `sunken`      | `#f5f4f2` | `#262523` | 입력 배경, 호버, 보조 버튼 |
| `line`        | `#e9e7e4` | `#302e2c` | 기본 구분선                |
| `line-strong` | `#d8d5d0` | `#403d3a` | 입력 테두리, 강조 구분     |
| `text`        | `#1b1a18` | `#eeebe7` | 본문                       |
| `text-2`      | `#6a6761` | `#a5a09a` | 보조 정보                  |
| `text-3`      | `#9b978f` | `#78736d` | 힌트, 비활성               |

### 강조 = 먹색

| 토큰        | 라이트    | 다크      |
| ----------- | --------- | --------- |
| `accent`    | `#1b1a18` | `#eeebe7` |
| `on-accent` | `#fbfaf9` | `#171615` |

주요 버튼은 라이트에서 검정, 다크에서 흰색이다. 브랜드 색이 따로 없다.

### 포커스

| 토큰    | 라이트    | 다크      |
| ------- | --------- | --------- |
| `focus` | `#4a6fa5` | `#7ba3d9` |

접근성상 눈에 보여야 하므로 유일하게 채도를 허용한다. 브랜드 색이 아니라
시스템 신호로 읽히도록 채도를 낮춘다.

### 상태

작품 사진·실 색과 경쟁하지 않도록 전부 채도를 낮춘다.

| 상태     | 라이트    | 다크      | 처리                                                       |
| -------- | --------- | --------- | ---------------------------------------------------------- |
| 진행중   | `accent`  | `accent`  | **유일하게 꽉 찬 알약** — 지금 손대는 것 하나만 두드러진다 |
| 계획중   | `#9b978f` | `#78736d` | `sunken` 배경 + 회색 글자                                  |
| 잠시멈춤 | `#5a7691` | `#8fabc4` | 차분한 슬레이트. **경고색을 쓰지 않는다**                  |
| 완성     | `#6b6a94` | `#a09fc9` | 흐린 보라                                                  |
| 풀어버림 | `#96635c` | `#c99a93` | 흐린 점토색                                                |

잠시멈춤에 노랑·주황을 쓰지 않는 것은 미적 선택이 아니라 이 서비스의 전제다.
중단은 경고할 일이 아니다.

### 실 색

카드의 얇은 세로선 하나가 그 프로젝트에 물린 실의 실제 색이다.
**화면에서 유일하게 자유로운 채도**이며, 사용자의 스태시에서 온다.
임의의 색을 UI가 만들어내지 않는다 — 실이 없으면 선도 없다.

## 3. 타이포그래피

### 서체

**Pretendard Variable** (동적 서브셋). 한글과 라틴을 한 가족이 담당한다.

전체 가변 폰트는 2MB라 PWA 프리캐시에 넣기 어렵다. 동적 서브셋은 32KB 조각을
필요할 때만 내려받고, 받지 못하면 시스템 한글 서체로 떨어질 뿐 앱 동작에는 지장이 없다.
오프라인 요구사항은 카운터가 도는 것이지 서체가 아니다.

숫자만 별도 서체를 쓰지 않는다. 대신 **고정폭 자형(`tabular-nums`)** 을 전역으로 켠다.

### 스케일

한국어는 라틴보다 행간이 더 필요하다. 본문 행간 1.7은 velog에서 가져온 값이다.

| 이름      | 크기 | 행간 | 자간     | 용도              |
| --------- | ---- | ---- | -------- | ----------------- |
| `display` | 34px | 1.2  | −0.02em  | 큰 숫자, 표지     |
| `title`   | 26px | 1.3  | −0.015em | 화면 제목         |
| `heading` | 20px | 1.4  | −0.01em  | 섹션              |
| `subhead` | 17px | 1.5  | 0        | 카드 제목         |
| `body`    | 15px | 1.7  | 0        | 본문              |
| `small`   | 13px | 1.6  | 0        | 보조 정보         |
| `caption` | 12px | 1.5  | 0        | 라벨, 힌트        |
| `micro`   | 11px | 1.4  | 0.06em   | 탭바, 대문자 라벨 |

**한글에 음수 자간을 넉넉히 주지 않는다.** 라틴에서는 조여야 좋아 보이지만
한글은 글자 폭이 균일해서 조이면 뭉친다. 큰 크기에서만 최소한으로 쓴다.

카운터의 큰 숫자는 이 스케일 밖이다(뜨기 모드는 별도 규칙).

## 4. 형태

| 토큰          | 값     | 용도                |
| ------------- | ------ | ------------------- |
| `radius-sm`   | 4px    | 칩, 알약, 작은 요소 |
| `radius-md`   | 6px    | 카드, 입력, 버튼    |
| `radius-lg`   | 12px   | 시트, 다이얼로그    |
| `radius-full` | 9999px | 아바타, 원형        |

노션에 가까운 작은 반경이다. 크게 둥근 모서리는 지금 앱이 가진 "AI 기본값" 인상의
큰 부분이었다.

**간격**은 4px 배수. 컴포넌트 내부는 8/12/16, 섹션 사이는 20/24/32.

**그림자**는 뜨는 것에만:
`shadow-overlay: 0 1px 3px rgb(0 0 0 / .08), 0 12px 32px -12px rgb(0 0 0 / .25)`

**터치 타깃**은 최소 44px. 뜨기 모드의 +1 영역은 화면 절반.

## 5. 컴포넌트 규칙

**버튼** — 주요는 먹색 채움, 보조는 `sunken` 배경, 고스트는 배경 없음,
위험은 `frogged` 글자색. 높이 44px, 반경 6px, 줄바꿈 금지.

**입력** — `surface` 배경 + `line-strong` 테두리. 포커스 시 테두리가 `focus`로
바뀌고 2px 링이 붙는다. 라벨은 `caption`, 위에 배치.

**카드** — `surface` 배경 + `line` 테두리, 그림자 없음. 호버 시 테두리만 `line-strong`으로.
실이 물려 있으면 왼쪽에 3px 실 색 세로선.

**상태 알약** — `micro` 크기, 반경 4px. 진행중만 채움.

**구분선** — 섹션 사이는 1px `line`. 목록 항목 사이는 선을 쓰지 않고 간격으로 나눈다
(선이 많으면 표처럼 보인다).

## 6. 아직 못 한 것

- ~~실 색 세로선~~ → 구현됨. 실 스태시와 프로젝트 배정이 들어오면서
  프로젝트 카드에 실제 실 색이 칠해진다. 색은 사용자가 실을 등록할 때 직접 고르며,
  실이 없거나 색을 안 정했으면 아무것도 그리지 않는다.
- ~~작품 사진~~ → 구현됨. 프로젝트 상세는 **마지막 모습 한 장을 크게** 보여주고
  나머지를 아래 줄에 담는다. 갤러리처럼 균일한 격자로 늘어놓지 않는 이유는
  사진의 용도가 감상이 아니라 복귀이기 때문이다. 사진에는 찍은 시점의 단수가
  박히므로("몸판 62단") 타임라인이 앨범이 아니라 진행 기록으로 읽힌다.
  목록·대시보드 카드의 대표 사진은 최신을 따라가고, 직접 고른 장만 고정된다.
- 사진 위에 글자를 얹지 않는다. 편물 색이 무엇이든 읽혀야 하는 값(단수·날짜)은
  사진 밖 헤어라인 아래에 둔다. 전체보기의 바탕만 예외적으로 어둡다 —
  사진은 실 색을 판단하는 근거이기도 해서 주변이 밝으면 색이 탁해 보인다.
- 계산 결과에는 도형을 함께 둔다. 게이지 조각 도식의 격자 한 칸은 10코 × 10단이고
  **정사각형이 아니다** — 실제 게이지 비율로 그려야 완성 모양을 보여줄 수 있다.
- 아이콘은 lucide 기본을 쓰고 있다. 뜨개 도구(바늘·타래·코) 아이콘은 별도 제작이 필요하다.
