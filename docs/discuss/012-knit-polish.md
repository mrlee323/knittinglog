## 쟁점

**실제로 뜨는 순간에 화면이 제 일을 하나.** 손은 실과 바늘에 묶여 있고, 화면은
팔 길이에 있고, 흘끗 보는 것은 숫자 하나다.

재보니 넷이 어긋나 있었다.

| 무엇           | 잰 값                                                   |
| -------------- | ------------------------------------------------------- |
| 단수 크기      | **72px 고정** — 아이패드에서 화면의 6.1%, SE에서 10.8%  |
| `+1` 면        | `bg-sunken` — **아래 보조 단추와 같은 회색**            |
| 도안 없을 때   | 안 올렸는데도 화면을 갈라 그 칸이 **화면의 38%**        |
| 화면 꺼짐 방지 | **끌 수 없고**, 잠금이 거부되면 화면에 아무 표시도 없다 |
| 상단 바 단추   | 34~38px — 이 앱이 정한 **44px 바닥 아래**               |

**자리 구분이 없어졌다.** 한 자리가 다 하고, 대신 **깨뜨려본 것을 전부 적는다.**

---

## 한 것

### 1. 단수를 화면 높이로 잰다

`text-7xl`(72px) 고정을 `clamp(4rem, 13vh, 9rem)`으로 바꿨다. 네 기기 모두
화면의 12~13%가 된다 — 87px(SE) · 106px(13 mini) · 110px(아이폰14) ·
144px(아이패드).

절대 크기가 기준이 아닌 이유는, 이 숫자를 **팔 길이에서 흘끗 보기** 때문이다.
큰 화면일수록 멀리 두고 보므로 같은 72px이 더 작게 읽힌다. `clamp`의 양끝이
보장이다 — 아주 낮은 창에서도 읽히는 밑값과, 아주 큰 화면에서 한 화면을 먹지
않는 윗값.

### 2. `+1`은 올라와 있고 보조 조작은 파여 있다

`+1` 면이 `bg-sunken`이었는데, 그건 `되돌리기`·`−1`·`여기에 라이프라인`과
**같은 면**이다. 화면에서 가장 크고 가장 많이 누르는 자리가 보조 단추와 같은
회색이라, 커다란 **빈 상자**로 읽혔다.

`bg-surface` + `shadow-raised`로 띄웠다. 강조색은 여전히 안 쓴다 — 화면 절반을
강조로 채우면 다크 모드에서 거의 흰 판이 되어 밤에 뜨는 사람 눈에 조명을
비추는 꼴이다(원래 주석이 그렇게 적혀 있었고, 그 제약은 그대로다). 기호 아래에
`+1` 글자도 붙였다. 기호만 있으면 "여기를 누르면 1이 오른다"가 아니라 "무언가를
추가한다"로도 읽힌다.

### 3. 볼 도안이 없으면 나누지 않는다

올려둔 것이 없어도 화면을 갈라 "작업대에 도안이나 참고 자료를 올려두면…" 한
줄을 띄웠다. 폰에서 그 칸이 **화면의 38%**였다 — 아무것도 없다는 말이 카운터보다
넓은 자리를 차지했다.

칸도 안내문도 토글도 **아예 안 그린다**(007·009와 같은 규칙). 올리는 길은
프로젝트의 `작업대` 탭과 개요의 `참고 자료`에 있고, **뜨는 중에 할 일이
아니다.**

### 4. 화면 꺼짐 방지를 단추로

`useWakeLock(true)` 고정이었고, **켜졌을 때만** 작은 해 아이콘이 떴다. 그러면
안 켜진 경우에 화면이 아무 말도 안 한다 — 배터리 절약 모드나 지원하지 않는
브라우저에서 거부되면 왜 화면이 꺼지는지 알 길이 없고 할 수 있는 것도 없다.

언제나 단추가 있고 상태를 말한다. 끌 수도 있다.

### 5. 상단 바 타깃 44px

`X` 38px, 해 34px, 도안 토글 34px. 이 앱은 "손에 실을 쥔 채 조작한다"는 이유로
44px을 바닥으로 잡아뒀는데(`Button`의 `icon` 주석), **상단 바만 그 바닥
아래**였다.

### 6. 자리가 모자라면 숫자 칸이 양보한다

카운터 칸의 원래 주석이 이렇게 적혀 있었다.

> 자리가 모자랄 때 밀려나야 하는 것은 읽는 정보이고, 마지막까지 남아야 하는
> 것은 누르는 자리다.

그런데 숫자 칸의 클래스가 `shrink-0`이라 **아무것도 줄지 않았고, 모자란 만큼
`+1`과 보조 조작이 아래로 잘렸다.** 주석과 코드가 반대였다.
`min-h-0 shrink overflow-y-auto`로 바꿨다.

## 관문 — `scripts/measure-knit.mjs`

| 관문 | 보는 것                                                           |
| ---- | ----------------------------------------------------------------- |
| A    | 단수가 **화면 높이에 비례**한다 (≥ 11%)                           |
| B    | `+1`이 보조 조작과 **다른 면**이고, 다크에서 **조명 판이 아니다** |
| C    | 도안이 없으면 도안 칸이 **아예 없다**                             |
| D    | 되돌리기 · 라이프라인 · 화면 꺼짐 방지가 **다 닿는다** (≥ 44px)   |
| E    | 도안을 켜도 `+1`과 보조 조작이 **화면 안에 남는다**               |

**E가 이 관문의 값어치다.** 012를 만들면서 **실제로 이 사고를 냈다.** 단수를
13vh로 키웠더니 812px 폰에서 도안을 켠 순간 `+1`과 보조 조작이 화면 밖으로
밀렸다. 도안을 끈 화면만 보면 멀쩡하고, **도안을 켜야만 드러난다.**

그래서 크기 기준을 창 높이(`short`)가 아니라 **"이 칸이 화면을 다 쓰는가"**
(`tight = short || splitting`)로 바꿨다. 812px 폰은 `short`가 아니면서 도안을
켜면 카운터가 화면의 62%만 받는다 — 창 높이로는 절대 안 잡히는 경우다.

**B는 두 테마를 다 잰다.** 다크에서 `+1` 면이 바탕보다 얼마나 밝은지를 본다.
"강조색을 쓰지 않는다"는 제약이 지켜지는지 색 이름이 아니라 **밝기로** 확인한다.

## 깨뜨려본 것 — 관문이 실제로 무나

일곱 번 깨뜨렸고 **일곱 번 다 물었다.**

| 깨뜨린 것                                 | 기대   | 실제                                                                     |
| ----------------------------------------- | ------ | ------------------------------------------------------------------------ |
| 단수를 `text-7xl` 고정으로 되돌림         | A 실패 | 종료 1 — 네 기기 전부(10.8 · 8.9 · 8.5 · 6.1%)                           |
| `+1`을 `bg-sunken`·그림자 없음으로 되돌림 | B 실패 | 종료 1 — 두 테마 전부, `보조 조작과 같은 면`                             |
| `+1`을 `bg-accent`로 바꿈                 | B 실패 | 종료 1 — `다크에서 바탕보다 139.8 밝다` (라이트는 통과, **다크만 문다**) |
| 도안이 없어도 나누게 되돌림               | C 실패 | 종료 1 — `도안 칸 820×404` · 안내문 · 토글. **A도 같이 물었다**          |
| 해 단추를 `p-2`로 되돌림                  | D 실패 | 종료 1 — `타깃이 34px이다`                                               |
| 숫자 칸을 `shrink-0`으로 되돌림           | E 실패 | 종료 1 — `SE에서 20px 밀려난다`                                          |
| `+1`의 `aria-label`을 지움                | **2**  | 종료 2 — `단수 또는 +1을 찾지 못했습니다` (조용히 통과하지 않는다)       |

세 번째 줄이 B를 두 테마로 잰 이유다. `bg-accent`는 **라이트에서는 통과한다** —
강조색이 어두운 녹색이라 바탕보다 어둡다. 다크에서만 연한 녹색이 되어 조명
판이 된다. 한 테마만 재면 이 사고가 그대로 통과한다(007의 A3가 다크를 봐야
했던 것과 같다).

### 깨뜨리기가 두 번 빗나갔다

`+1`의 클래스를 문자열로 치환하려다 두 번 실패했다. prettier가 클래스 순서를
재배열해(`active:shadow-none`이 뒤로 갔다) 내가 적은 문자열과 **파일의 문자열이
달랐다.** `assert`가 잡아서 파일이 안 바뀌었고, 줄 번호로 바꿔 다시 했다.

011에서 같은 일이 있었고 그때는 `assert`가 없어서 **깨뜨린 줄 알고 넘어갈
뻔했다.** 이번에는 모든 치환에 `assert`를 걸었다.

## 남는 것

- **"태블릿 이상은 도안+카운터 병렬"은 이미 되어 있었다.** `useWideEnough`
  (900px 이상)가 좌우 분할로 바꾼다. 012가 새로 한 것은 **볼 것이 없을 때
  안 나누는 것**뿐이다.
- **`+1` 면이 아이패드에서 화면의 50%다.** 큰 화면에서 누르는 면이 그만큼
  필요한지는 안 재봤다 — 폰이 실사용의 90%라는 전제라 지금은 그대로 둔다.
- **화면 꺼짐 방지 상태가 저장되지 않는다.** 화면을 나갔다 오면 다시 켜진다.
  꺼두고 싶은 사람에게는 매번 끄는 일이 되는데, 설정에 둘 값인지 이 화면이
  기억할 값인지는 안 정했다.
