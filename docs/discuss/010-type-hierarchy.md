## 쟁점

**색을 안 쓰기로 했으면 크기가 목소리를 내야 한다.** 그런데 재보니 숫자가
본문보다 **작았다.**

`docs/DESIGN.md`가 UI를 무채색으로 정했고 실과 사진만 색을 갖는다. 그러면
위계를 만들 수단은 크기·굵기·여백뿐인데, 상세 화면의 텍스트 잉크 중 **71.4%가
본문(15px)보다 작은 글자**였다. 13px과 12px이 화면을 반씩 나눠 덮고 있었다.

`WORKLIST.md:299`가 든 네 가지 중 둘(`word-break: keep-all`, `tabular-nums`)은
**이미 `body`에 걸려 있었다.** 네 화면 전부에서 위반 0개다. 010이 할 일은 그
둘을 새로 다는 것이 아니라 **다시 풀리지 않게 잠그는 것**이고, 나머지 둘(숫자
위계, 제목 스케일)이 진짜 일이었다.

**자리 구분이 없어졌다.** 018·008·009와 같다 — 한 자리가 다 한다. 대신
**깨뜨려본 것을 전부 적는다.**

## 한 화면만 보면 안 보이는 것

가장 큰 발견은 크기 자체가 아니라 **같은 사실이 화면마다 다른 크기**였다는
것이다.

| 사실          | 홈       | 상세     | 뜨기     |
| ------------- | -------- | -------- | -------- |
| 단수          | 34px     | 34px     | 72px     |
| **목표 단수** | **15px** | **20px** | **13px** |
| **남은 단수** | —        | **13px** | **13px** |

`/ 100`은 세 화면에서 세 크기였다. 한 화면만 열어 보면 어디도 이상하지 않다 —
각 화면 안에서는 나름 일관돼 보인다. **화면을 가로질러 재지 않으면 절대 안
보이는 종류**라, 관문 B가 그것만 본다.

## 한 것

### 1. 이름 붙은 숫자를 본문 위로

| 값                  | 전       | 후       | 왜                                                       |
| ------------------- | -------- | -------- | -------------------------------------------------------- |
| 남은 단수 (상세)    | 13px     | **17px** | 큰 숫자 다음으로 많이 읽히는 값인데 보조 설명으로 읽혔다 |
| 남은 단수 (뜨기)    | 13px     | **17px** | 상세와 같은 크기 — 같은 사실이다                         |
| 목표 단수 (홈)      | 15px     | **20px** | 상세와 같은 34px 숫자 옆이다                             |
| 목표 단수 (뜨기)    | 13px     | **20px** | 72px 옆에서 13px은 각주다                                |
| 게이지 요약 (상세)  | 13px     | **17px** | 이 섹션의 전부인 값이 설명문 크기였다                    |
| 실 잔량 (실 섹션)   | **없음** | **17px** | 아래 참고                                                |
| 카운터 행의 단수    | 12px     | **15px** | 행의 주인공은 이름이 아니라 단수다                       |
| 라이프라인 한 줄    | 12px     | **13px** | 이 서비스가 가장 앞세우는 문장이다                       |
| 뜨기 모드 버튼 라벨 | 11px     | **12px** | 팔 길이에서 실을 쥐고 누른다                             |

### 2. 실 잔량의 집을 정했다

008이 복귀 브리핑 한 줄에 `실 128g 남음`을 넣었다. 그런데 **실 섹션은 잔량을
아예 보여주지 않았다** — 잰 무게가 있어도 저울 아이콘을 눌러 시트를 열어야
알 수 있었다.

규칙을 이렇게 정했다. **요약 줄은 조용히 두고, 그 값을 소유한 섹션이 크게
말한다.** 브리핑의 재료 줄은 여러 사실을 `·`로 잇는 한 줄이라 숫자 하나만 키울
수 없고, 키우면 008이 만든 그 줄이 깨진다. 그래서 실 행의 오른쪽에 `128g`을
17px로 놓았다.

잰 적이 없으면 아무 말도 하지 않는다 — 0g으로 치면 "실이 없다"는 거짓이 된다
(008이 `domain/yarn`에 적은 규칙과 같다).

### 3. 섹션 제목을 본문 위로

다섯 섹션의 `h2`가 15px/500이었다. 본문이 15px/400이니 **굵기만으로** 갈리고
있었다. 17px(`text-subhead`)로 올려 스케일이 갈리게 했다.

이제 상세의 층은 이렇다 — 34 (단수) · 26 (화면 제목) · 20 (목표) · 17 (섹션
제목 · 남은 단 · 게이지 · 잔량 · 바늘) · 15 (본문 · 카드 제목) · 13 (탭·버튼) ·
12 (보조) · 11 (레이블).

## 관문 — `scripts/measure-type.mjs`

| 관문 | 보는 것                                                       |
| ---- | ------------------------------------------------------------- |
| A    | 이름 붙은 숫자가 **본문보다 크다**                            |
| B    | 같은 사실이 **화면이 바뀌어도 같은 크기**다                   |
| C    | 섹션 제목 > 본문 > 보조 설명 — 크기로 갈린다                  |
| D    | 본문보다 작은 글자가 텍스트 잉크의 **60%**를 넘지 않는다      |
| E    | `keep-all` · `tabular-nums`가 **모든 화면에서 실제로** 걸린다 |

**본문 크기를 상수로 박지 않는다.** `body`의 계산된 `font-size`를 읽어 그것을
기준으로 비교한다. 15px을 관문에 박아두면 `--text-body`를 고친 날 관문이
눈치채지 못한다 — 015가 정확히 그렇게 통과했다.

**잎 요소만 세지 않는다.** `<p>62<span>/100</span></p>`에서 `62`는 자식이 있는
요소의 자기 텍스트라, 잎만 보면 **큰 숫자가 통째로 빠진다.** 처음 짠 조사
스크립트가 그랬고, 상세의 34px `62`를 못 보고 있었다.

**D는 면적이 아니라 잉크로 잰다** — 글자 수 × 크기². 요소 `width`로 재면 한
줄짜리 큰 글자가 짧아서 작게 잡히고 빽빽한 작은 글자가 크게 잡혀, 눈이 받는
인상과 반대로 센다.

### 본문 미만 글자가 덮는 잉크

| 화면 | 고치기 전 | 고친 뒤   | 상한 |
| ---- | --------- | --------- | ---- |
| 홈   | 46.7%     | 44.2%     | 60%  |
| 목록 | 42.5%     | 42.5%     | 60%  |
| 상세 | **71.4%** | **52.3%** | 60%  |
| 뜨기 | 57.5%     | 49.3%     | 60%  |

**상한을 55%로 조이지 않았다.** 그러면 고치기 전 뜨기(57.5%)도 잡히지만 고친 뒤
상세가 52.3%로 여유 2.7%뿐이다 — 글자 하나 늘고 주는 것에 흔들리는 관문은
엉뚱한 이유로 깨지고, 그러면 아무도 안 믿는다. 60%는 상세의 71.4%를 잡고
52.3%에 7.7% 여유를 둔다. 뜨기의 57.5%는 이 관문이 아니라 A·B가 잡았다.

## 깨뜨려본 것 — 관문이 실제로 무나

여섯 번 깨뜨렸고 **여섯 번 다 물었다.**

| 깨뜨린 것                                                                   | 기대   | 실제                                                                              |
| --------------------------------------------------------------------------- | ------ | --------------------------------------------------------------------------------- |
| 게이지 섹션만 010 이전으로 되돌림                                           | A 실패 | 종료 1 — `게이지가 13px이다`. **C·D도 같이 물었다**(제목 15px, 상세 잉크 61.2%)   |
| 뜨기 모드만 010 이전으로 되돌림                                             | B 실패 | 종료 1 — `남은 단수 상세 17px · 뜨기 13px`, `목표 단수 홈 20 · 상세 20 · 뜨기 13` |
| 진행도 카드의 큰 숫자에 `font-variant-numeric:normal` + `word-break:normal` | E 실패 | 종료 1 — `상세에 keep-all 아님 2개 · tabular 아님 2개` (`62`, `/100`)             |
| 실 행에서 `128g`을 지움                                                     | **2**  | 종료 2 — `"실 잔량"(/^128g$/)을 찾지 못했습니다` (조용히 통과하지 않는다)         |
| 010 전체를 되돌림                                                           | **2**  | 종료 2 — 같은 이유. 되돌리면 크기가 주는 게 아니라 **사실 하나가 사라진다**       |

두 번째 줄이 이 관문의 존재 이유다. 뜨기 모드만 보면 72px 숫자가 있어 위계가
멀쩡해 보이고, 상세만 보면 17px이 맞다. **둘을 같이 재야만** 같은 값이 다른
크기라는 게 드러난다.

세 번째 줄은 007·015가 반복한 종류다 — 규칙은 `body`에 멀쩡히 있고 CSS도
정상인데, 자손 하나가 덮으면 **화면에서만 조용히 풀린다.**

## 남는 것

- **목록 화면은 손대지 않았다.** 42.5%로 관문을 통과하고, 카드가 이름(17px) +
  보조(12px) 두 층이라 위계가 이미 갈려 있다. 011이 넓은 화면을 만질 때 같이
  본다.
- **`text-small`(13px)이 아직 상세 잉크의 27%다.** 탭·버튼 라벨·정의 목록이
  그 크기를 공유하는데, 셋은 역할이 다르다. 013의 시각 언어 정리에서 볼
  자리다 — 지금 나누면 근거 없이 나누는 것이 된다.
- **`text-caption`과 `text-micro`의 경계가 흐리다.** 11px과 12px이 각각 보조
  설명과 레이블인데, 화면에 따라 서로의 자리를 쓴다. 같은 이유로 013에 남긴다.
