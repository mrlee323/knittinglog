## 쟁점

**태블릿·PC에서 폰 레이아웃을 가운데 둔 것처럼 보이나.**

재보니 그랬다. 본문 폭이 **960px에 못 박혀 있어서** 화면이 커져도 그대로였다.
1920px에서 본문이 쓸 수 있는 가로(뷰포트 − 고정 내비 224px = 1696px)의 **57%**만
덮었고, 프로젝트 목록은 1280px에서든 1920px에서든 **3열에서 멈췄다** — 폭이
늘어난 만큼 카드만 커졌다.

홈은 두 단인데 **오른쪽이 왼쪽의 절반도 안 찼다** — 545 / 265. `기다리는 중`
행이 576px을 혼자 쓰면서 가운데가 비었고, `뜨기` 버튼이 576px로 늘어나 왼쪽
단만 길어졌다.

`docs/DESIGN.md`와 `__root.tsx`가 **기준 화면을 태블릿·PC**로 못 박았다. 폰이
아니라 이쪽이 기본인데, 기본 화면이 폰 레이아웃을 가운데 둔 모양이었다.

**자리 구분이 없어졌다.** 한 자리가 다 하고, 대신 **깨뜨려본 것을 전부 적는다.**

---

## 한 것

### 1. 폭 상한을 한 단계 더 (2xl)

`Page`의 `wide`가 `md:max-w-5xl`에서 멈췄다. `2xl`(1536px+)에서 `88rem`까지
간다. 읽기 폭(`wide` 아님 — 폼·설정)은 **그대로 둔다.** 거기서 넓히면 줄만
길어져 읽기가 나빠진다.

### 2. 열이 한 줄 더 는다

`CardGrid`가 `sm:2 · xl:3`에서 멈췄다. `2xl`에서 한 열 더 — 프로젝트 4열, 실·
게이지 3열. **폭이 늘었는데 열이 그대로면 카드만 커지고, 카드가 커지는 것은
정보 밀도가 아니다.**

`Columns`의 옆 단도 `2xl`에서 22rem → 28rem. 같은 이유다 — 늘어난 자리를 본문
한 단이 혼자 먹으면 카드가 커지기만 한다.

### 3. 홈의 두 단을 다시 잡았다

- `기다리는 중`을 `xl`에서 **두 열**로. 한 줄에 이름·사유·배지만 있는 행이라
  576px을 혼자 쓰면 가운데가 빈다.
- 복귀 카드의 `뜨기`를 **넓은 화면에서 숫자 옆**으로. 폰에서 버튼이 폭을 꽉
  채우는 건 엄지가 닿는 자리를 만드는 일인데, 1280px에서 576px짜리 버튼은
  그 이유가 사라지고 카드만 길어진다.

### 4. 상세의 `뜨기`도 같다

1920px에서 진행도 카드의 `뜨기`가 **920px**이었다. 완성 예상 옆으로 옮겼다 —
홈의 복귀 카드와 같은 규칙이다.

## 관문 — `scripts/measure-wide.mjs`

| 관문 | 보는 것                                          |
| ---- | ------------------------------------------------ |
| A    | 두 단 화면에서 **오른쪽이 비지 않는다**          |
| B    | 폭이 오르면 목록의 **열 수가 오른다**            |
| C    | 본문이 **쓸 수 있는 가로**를 쓴다                |
| D    | **폰이 깨지지 않는다** — 375px에서 가로 스크롤 0 |

**A는 비율이 아니라 "빈 띠"로 잰다.** 처음에는 `오른쪽 / 왼쪽 ≥ 0.5`로 짰는데,
고치기 전 값이 **0.49**였다 — 0.01 차이로 물었다. 그런 관문은 통과해도 아무것도
보장하지 않는다. 비율은 두 단이 **둘 다 짧을 때**도 나쁘게 나오는데 그때는 눈에
비어 보이지 않는다. 눈이 보는 것은 비율이 아니라 **화면에서 그 띠가 차지하는
자리**다. 그래서 `(왼 − 오) / 화면 높이 ≤ 25%`로 바꿨다 — 고치기 전 31%, 고친 뒤
17%로 양쪽에 여유가 있다.

**C는 뷰포트가 아니라 "쓸 수 있는 가로"로 나눈다.** 큰 화면에는 왼쪽에 고정
내비가 있어서 뷰포트로 나누면 **내비를 죽은 여백으로 센다.** 내비는 죽은 여백이
아니다.

**D가 없으면 A·B·C를 폰을 부수면서 통과할 수 있다.** 넓은 화면을 채우는 가장
쉬운 방법은 폭 상한과 열 수를 올리는 것이고, 둘 다 폰에서 터진다. D는 열 수가
아니라 **가로 스크롤**을 본다 — `지금 상태` 타일처럼 폰에서도 일부러 여러 열인
격자가 있어서, 열 수를 세면 멀쩡한 것을 잡는다.

### 잰 값

| 관문                            | 고치기 전 | 고친 뒤 | 기준  |
| ------------------------------- | --------- | ------- | ----- |
| A 홈의 빈 띠 (1280px)           | **31%**   | 17%     | ≤ 25% |
| A 상세의 빈 띠                  | 0%        | 0%      | ≤ 25% |
| B 프로젝트 열 (1920px)          | **3열**   | 4열     | ≥ 4열 |
| B 실·게이지 열 (1920px)         | **2열**   | 3열     | ≥ 3열 |
| C 본문/쓸 수 있는 가로 (1920px) | **57%**   | 79%     | ≥ 70% |
| C 1280px                        | 91%       | 91%     | ≥ 70% |
| D 폰 가로 스크롤                | 0px       | 0px     | = 0px |

1280px에서는 원래 91%라 C가 물지 않는다. **완료 기준 1이 말하는 1280px의
"오른쪽이 비어 보인다"는 가로가 아니라 세로였고**, 그건 A가 잡는다.

## 깨뜨려본 것 — 관문이 실제로 무나

다섯 번 깨뜨렸고 **다섯 번 다 물었다.** 그런데 한 번은 **깨뜨린 줄 알았는데 안
깨져 있었다.**

| 깨뜨린 것                                          | 기대   | 실제                                             |
| -------------------------------------------------- | ------ | ------------------------------------------------ |
| 홈의 두 열·`뜨기` 옆배치를 되돌림                  | A 실패 | 종료 1 — `빈 띠 280px(화면의 31%)`               |
| `CardGrid`의 `2xl` 한 단계를 뺌                    | B 실패 | 종료 1 — 세 줄(프로젝트 3열, 실 2열, 게이지 2열) |
| `Page`의 `2xl` 폭 상한을 뺌                        | C 실패 | 종료 1 — `1920px에서 57%만 덮는다`               |
| `CardGrid`를 `repeat(4, minmax(18rem,1fr))`로 고정 | D 실패 | 종료 1 — `폰 목록에서 가로로 829px 넘친다`       |
| `Columns`를 한 단(`flex-col`)으로 바꿈             | **2**  | 종료 2 — `홈가 1280px에서 두 단이 아닙니다`      |

### 안 깨진 깨뜨리기

C를 깨뜨리려고 `wide ? "…2xl:max-w-[88rem]" : "…"` 한 줄을 문자열 치환했는데,
**prettier가 그 삼항식을 이미 세 줄로 쪼개 둬서 치환이 아무것도 안 했다.**
그대로 관문을 돌렸다면 "C는 안 문다"고 적을 뻔했다.

`assert`를 빼먹은 치환 하나가 원인이다. 006에서 `<CoverThumb className>`이
조용히 버려졌던 것과 **같은 종류**다 — 깨뜨리기는 깨뜨렸다는 것 자체를
확인해야 한다. 고친 파일을 다시 읽어 바뀐 줄을 눈으로 본 뒤 다시 돌렸고,
그때 물었다.

## 남는 것

- **홈의 빈 띠 17%는 없어지지 않는다.** 오른쪽은 집계 둘로 끝나는 단이고, 거기
  뭘 더 넣으려면 **없는 내용을 만들어야 한다**(001 결정 6이 금지한 장식). 지금
  구조에서 이게 바닥이다.
- **`실` 목록의 `NaN타래`는 관문 데이터의 흠이지 앱의 흠이 아니다.** 처음 심은
  데이터에 `skeinCount`를 빼먹어서 나왔다 — Dexie에 직접 쓰면 zod 검증을
  건너뛴다. 실제 경로(`createYarn`)는 그 값을 필수로 받는다. 관문 데이터에
  값을 채웠다.
- **1440px은 79%로 통과하지만 상한이 안 올라간다**(Tailwind `2xl`이 1536px).
  1440은 흔한 노트북 폭이라 한 단계를 1400 근처로 내리는 것도 방법인데,
  기준점을 바꾸는 일이라 013에서 시각 언어를 정리할 때 같이 본다.
