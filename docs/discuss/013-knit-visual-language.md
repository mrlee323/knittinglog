## 방향은 사람이 골랐다

`WORKLIST.md`가 후보 셋(계기 · 염색 · **니트**)을 나란히 두고 남겨둔 자리다.
제품의 정체성이라 **사람이 골랐고, 니트다** — 메리야스 조직, 부드러운 반복,
초보 친화. 자주 멈추지만 다시 시작하고 싶은 사람이 대상이다.

그 선택이 맞는 이유는 이 앱의 전제와 같기 때문이다. `AGENTS.md`가 "중단은
실패가 아니다"라고 적었고 `docs/DESIGN.md`가 가장 많이 중단하는 사람은
초보라고 적었다. 계기(정확성)는 완료 기준 1("생산성 도구가 아니라 작업대처럼")과
반대로 가고, 염색(작품 사진)은 **사진이 없는 첫날**(007이 다룬 그 화면)에서
가장 불리하다.

**자리 구분이 없어졌다.** 한 자리가 다 하고, 대신 **깨뜨려본 것을 전부 적는다.**

## 쟁점 — 덜어내기만 하면 밋밋해진다

008~012가 화면에서 계속 덜어냈다. 009가 빈 섹션 다섯을, 007이 결핍 블록을,
012가 도안 없는 칸을 없앴다. 빈 프로젝트 상세는 1916px에서 999px이 됐다.

그런데 013의 완료 기준 둘째가 **"사진이 없어도 화면이 밋밋하지 않다"**다.
덜어낸 자리를 무엇으로 채우나.

**색으로는 못 채운다.** 원칙 1이 "화면의 주인공은 사진과 실"이고 017이 방금
"꽉 채운 강조 단추는 한 화면에 하나"로 좁혔다. **그림으로도 못 채운다** —
001 결정 6이 장식 그래픽을 금지했다.

남는 것이 **질감**이다. 채도 0이라 사진·실 색과 경쟁하지 않고, 뜨개에서 온
형태라 발명한 그림이 아니다.

## 한 것

### 1. 메리야스 조직 한 벌

코 머리의 아치를 한 줄 그리고 다음 줄을 **반 코 어긋나게** 쌓는다. 어긋남이
없으면 격자로 읽힌다 — 실제로 격자·마름모 변형을 먼저 그려봤고 둘 다 아가일이나
철망이었다.

| 토큰               | 라이트               | 다크                    | 뜻          |
| ------------------ | -------------------- | ----------------------- | ----------- |
| `--knit-cell-w/h`  | 13px / 16px          | 같음                    | 코 하나     |
| `--knit-ink`       | `rgb(27 26 24/.11)`  | `rgb(251 250 249/.10)`  | 천이 주인공 |
| `--knit-ink-faint` | `rgb(27 26 24/.022)` | `rgb(251 250 249/.022)` | 천이 배경   |

이미지가 아니라 그라디언트다 — 에셋이 없으니 다크 대응이 토큰 하나로 끝나고
확대해도 안 깨진다.

### 2. 세 곳뿐이다

| 자리                      | 세기         | 왜                                      |
| ------------------------- | ------------ | --------------------------------------- |
| 작업대 바탕               | `knit-faint` | 화면이 놓인 바닥이다                    |
| 실 스와치(목록 카드 윗면) | `knit-face`  | 실은 **뜰 것**이지 페인트 견본이 아니다 |
| 뜨기 모드의 `+1` 면       | `knit-face`  | 천 위를 누르면 한 단이 쌓인다           |

여기 없는 곳에 깔면 **무늬 배경**이 되고, 그 순간 원칙 1이 깨진다.

**빈 스와치 격자는 그대로 둔다.** 사진도 실도 없는 카드 윗면의 16코 12단
격자(007)는 "아직 기록 전"이라는 뜻이다. 거기에 조직을 채우면 **"이미 떴다"**가
된다 — 없는 사실을 그리는 것이라 001 결정 6에 걸린다. 조직은 **실이 있을 때**
그 색 위에만 얹힌다.

### 3. 그림자 규칙을 정리했다

012가 `+1` 면에 `shadow-raised`를 붙였는데, `docs/DESIGN.md`는 **"그림자는
화면 위에 뜨는 것에만"**이라고만 적혀 있었고 `shadow-raised`는 문서에 아예
없었다(토큰과 `/design` 화면에는 있었다). 문서와 코드가 어긋난 자리다.

원칙 2를 다시 썼다 — **구분**에는 안 쓰고, 붙는 자리는 둘이다.

| 언제                | 토큰             |
| ------------------- | ---------------- |
| 화면 **위에** 뜬 것 | `shadow-overlay` |
| **눌리는 것** 하나  | `shadow-raised`  |

그리고 **한 화면에 `shadow-raised`는 하나**다 — 여럿이 떠 있으면 다시 "어느
것을 누르지"가 된다(017이 강조색에 대해 정한 것과 같다).

### 4. 반경은 키우지 않았다

니트 방향이 "부드러운 반복"이라고 해서 모서리를 키우지 않는다. `DESIGN.md`가
작은 반경을 고른 이유가 **"AI 기본값" 인상을 없애는 것**이었고, 부드러움은
조직이 만든다. `radius-lg`(12px)에 `+1` 면을 더한 것만 예외다 — 96~590px짜리
손으로 누르는 판이라 6px에서는 뻣뻣하다. 시트와 같은 이유(손이 닿는 큰 면)다.

## 관문 — `scripts/measure-knit-language.mjs`

| 관문 | 보는 것                                                     |
| ---- | ----------------------------------------------------------- |
| A    | 조직이 **세 곳에 실제로 걸린다** — 화면 픽셀에서, 두 테마로 |
| B    | 조직이 **사진과 실 색을 이기지 않는다**                     |
| C    | `shadow-raised`가 **한 화면에 하나**                        |
| D    | `radius-lg`가 **시트와 `+1` 면에만**                        |
| E    | `docs/DESIGN.md`가 아직 같은 값을 말한다                    |

**A는 클래스가 붙었는지가 아니라 픽셀을 본다.** 013을 만들면서 `.knit-faint`가
마크업에 멀쩡히 있는데 화면에는 아무것도 안 걸린 상태를 실제로 만들었다
(아래 참고). 클래스를 세는 관문이었다면 통과했을 것이다.

**B가 013의 진짜 위험이다.** 질감은 늘릴수록 "뜨개답다"고 느껴지는데 원칙 1은
늘릴수록 깨진다.

### 잰 값 (375×812 · 두 테마 · 채널차)

| 자리        | 라이트 | 다크 | 최소 | 최대 |
| ----------- | ------ | ---- | ---- | ---- |
| 작업대 바탕 | **6**  | 6    | 4    | 9    |
| 실 스와치   | 15     | 12   | 4    | 40   |
| `+1` 면     | 26     | 23   | 4    | 40   |

바탕의 6은 **007이 "잉크"로 세는 문턱과 같다.** 가까이서 보면 천이고 멀리서는
그냥 바탕이다. 처음에 0.055로 잡았을 때는 13이었고, 화면 전체를 덮으니
**무늬 배경**이었다 — 눈으로 보고 내렸다.

## 세 번 헛디뎠다

013은 CSS를 건드리는 첫 스레드였고, 셋 다 **관문이 있어도 조용히 통과했을**
종류였다.

### 하나 — `@apply`가 CSS 전체를 깨뜨렸다

`body`에 `@apply knit-faint`를 썼다. Tailwind v4에서 `@layer utilities`의
클래스는 `@apply`가 못 찾고, 그러면 경고가 아니라 **CSS 컴파일 전체가
실패한다.** 개발 서버가 `/src/index.css`에 500을 내고 화면이 **스타일 없이**
떴다.

### 둘 — 그때 나는 그걸 못 봤다

스크린샷이 멀쩡했기 때문이다. **다른 포트(5174)의 낡은 개발 서버를 찍고
있었다.** 세션 내내 거기를 쟀는데, `index.css`를 고치기 전까지는 그 서버도
같은 트리를 서빙하고 있어서 티가 안 났다.

잡은 것은 관문이 아니라 **픽셀을 직접 재보려다가**였다 — `getComputedStyle`로
조직이 안 걸린 걸 보고 역추적했다. 관문을 낡은 서버에 겨누면 관문도 같이
속는다.

### 셋 — 그라디언트는 커스텀 속성에 담을 수 없다

기하를 한 자리에서 만들려고 `--knit-image`에 그라디언트를 넣고 쓰는 쪽에서
`--knit-tone`만 갈아끼우려 했다. 안 된다 — **커스텀 속성의 치환은 선언된
요소에서** 일어난다. `:root`에 `--knit-tone`이 없으니 `--knit-image`가 거기서
이미 무효가 되고, 쓰는 쪽에서 무엇을 넣든 `none`이다. 클래스로 옮겼다.

이 셋 때문에 관문 A를 **클래스가 아니라 픽셀**로 재게 됐다.

## 깨뜨려본 것

여섯 번 깨뜨렸고 **여섯 번 다 물었다.** 그중 하나는 **관문을 고쳐야** 물었다.

| 깨뜨린 것                                | 기대   | 실제                                                              |
| ---------------------------------------- | ------ | ----------------------------------------------------------------- |
| 루트에서 `knit-faint`를 뺌               | A 실패 | 종료 1 — 두 테마 모두 `작업대 바탕에 조직이 안 걸렸다 — 채널차 0` |
| `--knit-ink-faint`를 0.055로 되돌림      | B 실패 | 종료 1 — `채널차 13 (최대 9)`                                     |
| 목록 카드 윗면을 `rounded-lg`로          | D 실패 | 종료 1 — `허용되지 않은 자리에 있다 — DIV`                        |
| 보조 조작 셋에 `shadow-raised`를 붙임    | C 실패 | 종료 1 — `뜨기에 shadow-raised가 4개다`                           |
| `DESIGN.md`의 절 제목만 바꿈             | E 실패 | 종료 1 — `절을 고쳤으면 이 관문도 같이 고친다`                    |
| 그림자 탐침을 `style.boxShadow`로 되돌림 | **2**  | 종료 2 — `하나도 찾지 못했습니다 — 탐침이 실제 값과 안 맞습니까?` |

### C가 처음에 조용히 통과했다

그림자를 세는 탐침을 `probe.style.boxShadow = "var(--shadow-raised)"`로 만들었다.
Tailwind의 `shadow-raised` 유틸은 `--tw-*`를 엮어 **다른 문자열**을 계산해서
한 번도 안 맞았고, 관문은 모든 화면에서 **0개**를 세며 통과했다.

017에서 `--color-accent`를 깨뜨렸을 때와 **같은 함정**이다 — 셀 것이 사라지면
세기는 늘 성공한다. 같은 방법으로 막았다: 뜨기 모드에는 `+1` 면이 언제나 있고
그 면이 `shadow-raised`를 가지므로, 거기서 0개면 화면이 아니라 **재는 쪽이
깨진 것**이라 환경 문제(2)로 끝낸다.

  CHROMIUM_PATH=/opt/pw-browsers/chromium \
  node scripts/measure-knit-language.mjs

종료코드: 0 통과 · 1 관문 실패 · 2 환경 문제.

**개발 서버가 지금 트리를 서빙하는지 먼저 본다.** 낡은 서버를 겨누면 관문이
같이 속는다 — 이 스레드에서 실제로 그랬다.

**관문을 돌리는 동안 트리를 건드리지 않는다.** 파일을 고치면 Vite가 페이지를
다시 읽고, 그 순간 재던 관문이 요소를 못 찾아 **환경 문제(2)로 끝난다.** 이
세션에서 두 번 그랬고(008·012), 둘 다 따로 돌리면 통과했다. 종료코드 2는
"화면이 틀렸다"가 아니라 "재는 조건이 틀렸다"이므로, 2가 나오면 **먼저 조용한
트리에서 한 번 더 돌려본다.**

## 남는 것

- **완료 기준 1("작업대처럼 보인다")은 잰 것이 아니다.** 조직·그림자·반경은
  쟀지만 "작업대처럼"은 사람이 보고 판단할 몫이다. 014(실기기 검증)에서 같이
  본다.
- **조직이 스크롤에 붙어 있다.** 바탕이 루트 요소에 깔려 있어 스크롤하면 같이
  움직인다. 고정(`background-attachment: fixed`)이 더 작업대답지만 모바일
  사파리에서 성능 문제가 알려져 있어 안 건드렸다.
- **`+1` 면이 아이패드에서 화면의 50%다**(012에서 남긴 것). 이제 그 면 전체가
  천이라 더 두드러진다 — 큰 화면에서 적절한지는 014에서 실기기로 본다.
