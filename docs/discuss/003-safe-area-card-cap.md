## 쟁점

001에서 홈 첫 카드의 사진은 **1:1을 넘지 않는다**고 정했다. 그런데 그 값은
헤드리스 390×844 기준이고, 002가 닫히면서 안전영역이 붙은 실기기에서는 1:1도
간당간당할 수 있다는 이월 항목이 남았다.

이번 태스크는 카드 디자인을 다시 고르는 일이 아니다. **005·006에서 이미지형 카드와
홈 첫 카드를 크게 바꾸기 전에, 모바일 safe-area가 붙어도 첫 화면 안에 복귀 행동이
남는지 확정하는 일**이다.

틀리면 잃는 것: 사진을 크게 만들어 예뻐졌는데, 정작 사용자가 앱을 열자마자 눌러야
하는 `뜨기` 버튼이 첫 화면 아래로 밀린다. 그러면 이 앱은 "예쁜 갤러리"는 되어도
"그 자리에서 이어 뜨는 기록장"은 아니게 된다.

## 선택지

**A. 001의 1:1 상한을 그대로 둔다** — `DESIGN.md`의 현재 결정을 유지한다.
포기하는 것: 실제 safe-area에서 CTA가 아슬아슬하면 005·006 구현 뒤에 다시 카드
비율을 줄여야 한다.

**B. 1:1은 유지하되 관문을 더 엄격하게 둔다** — 사진은 1:1까지 허용하지만,
측정 관문은 `뜨기` CTA의 하단이 탭바/안전영역 위에 확실히 남아야 통과로 본다.
포기하는 것: 1:1이 이론상 가능해도 문구·숫자·여백이 늘면 바로 탈락하므로
홈 첫 카드의 정보량을 강하게 제한해야 한다.

**C. 홈 첫 카드만 더 낮은 비율로 낮춘다** — 예를 들어 4:3 이하로 고정하고,
목록 카드는 별도 규칙을 둔다.
포기하는 것: 사용자가 원하는 "작품이 먼저 보이는" 감정적 첫인상이 약해진다.
사진이 작은 관리툴 인상으로 돌아갈 위험이 있다.

## 대화

### 기획 · 2026-08-29 · 1왕복

**B를 우선안으로 본다.** 001의 결정 자체는 아직 뒤집지 않는다. `DESIGN.md:178-187`의
핵심은 사진을 작게 만들자는 것이 아니라, **복귀 화면에서는 단수와 `뜨기` 버튼이
사진보다 늦게 사라지면 안 된다**는 것이다. 그래서 비율 숫자를 먼저 낮추기보다,
CTA가 실제로 살아 있는지 재는 관문을 더 정확하게 만드는 편이 맞다.

근거는 셋이다.

1. `docs/DESIGN.md:184-187`은 390×844에서 카드 상단 74px, 탭바 상단 786px,
   카드 내부 폭 326px, 사진 아래 요소 228px을 근거로 1:1 상한을 정했다. 이 값은
   재본 숫자지만 safe-area 0 조건이다.
2. `docs/discuss/002-personas.md:278-287`은 아이폰 안전영역을 산수로 넣으면 1:1의
   남는 높이가 158px에서 77px로 줄 수 있다고 남겼다. 스레드가 직접 말하듯 이것은
   잰 값이 아니라 산수다. 이번 003은 이 산수를 실제 측정으로 바꾸는 작업이다.
3. 이미 `scripts/measure-safe-area.mjs`가 들어왔다. 주석은 "안전영역 0으로 001의
   값을 재현하지 못하면 새 숫자도 믿을 수 없다"고 적고 있다
   (`scripts/measure-safe-area.mjs:1-6`). 방향은 맞다.

다만 지금 스크립트만으로는 003을 닫기 어렵다. 보완이 필요하다.

- `scripts/measure-safe-area.mjs:73-87`은 첫 카드의 상단·폭과 nav 위치만 잰다.
  이번 태스크의 판정 대상은 카드가 아니라 **`뜨기` CTA**다. CTA의 `top`/`bottom`,
  탭바 상단과의 간격, 첫 viewport 안 노출 여부를 재야 한다.
- `scripts/measure-safe-area.mjs:36-45`는 측정용 프로젝트를 매번 추가하고 개수만
  반환한다. 기존 IndexedDB 데이터가 남아 있으면 첫 카드가 측정용 프로젝트가 아닐
  수 있다. 001의 값을 재현하는 관문이라면 측정 전에 DB를 비우거나, 측정 대상
  프로젝트를 id로 찾아야 한다.
- `scripts/measure-safe-area.mjs:97-99`는 아이폰14 가정값 하나만 본다. 최소한
  safe-area 0, 47/34, 59/34 세 조건은 표로 남겨야 한다. 47/34와 59/34는
  `docs/discuss/002-personas.md:284-285`에 이미 "가정값"으로 남은 값이다.
- 주석의 "관문"은 아직 코드의 관문이 아니다. `scripts/measure-safe-area.mjs:92-109`는
  출력만 하고 실패 조건으로 종료하지 않는다. `npm` 스크립트로 묶든, node 스크립트
  자체에서 non-zero exit을 내든, 검증이 다시 돌릴 수 있는 실패 조건이 필요하다.

기획 기준은 이렇게 둔다.

| 항목        | 통과 기준                                                                                                                                                  |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 재현 관문   | safe-area 0에서 001의 주요 값이 같은 구조로 다시 나온다. 값이 조금 달라졌다면 왜 달라졌는지 파일·줄 번호로 설명한다                                        |
| CTA 관문    | 390×844에서 safe-area를 넣어도 홈 첫 카드의 `뜨기` CTA 전체가 탭바 위에 보인다                                                                             |
| 여유 관문   | CTA 하단과 탭바 상단 사이에 최소 24px 여유가 남는다. 24px은 손가락 터치 목표 44px의 절반 정도라, "보이긴 함"과 "안심하고 누름"을 가르는 최소 여백으로 둔다 |
| 정보량 관문 | 이 관문을 통과하려고 프로젝트명, 현재 단수, 진행률, 마지막 작업 시점 중 핵심 정보를 숨기지 않는다. 줄일 수 있는 것은 사진 높이와 장식 여백이다             |

내가 다시 반대할 조건도 적는다. 측정 결과 1:1이 24px 여유를 못 남기면 **C로
내려가야 한다.** 이 앱에서 사진은 중요하지만, 홈 첫 카드는 이미 고른 작품으로
돌아오는 카드다. `docs/DESIGN.md:178-182`의 결정처럼 복귀 카드의 주인공은 사진
혼자가 아니라 단수와 `뜨기`다. 사진 때문에 `뜨기`가 밀리면 001의 정신을 어긴다.

반대로 1:1이 24px 이상 여유를 남기면, 005·006은 안심하고 1:1 상한을 유지한 채
디자인으로 들어가면 된다. 그때 Claude는 목록 카드와 홈 첫 카드를 분리해 구현해야
한다. 목록은 "고르는 화면"이라 사진과 이름이 먼저이고, 홈 첫 카드는 "복귀 화면"이라
단수와 `뜨기`가 먼저다.

**넘김: 구현** — 묻는 것: 지금 측정 스크립트를 CTA 기준으로 보완해서 실제 숫자를
낼 수 있나. 특히 1) 측정용 데이터 고정, 2) CTA bottom과 탭바 top 간격, 3) safe-area
0/47/34/59/34 표, 4) 실패 시 non-zero exit까지 넣어달라. 측정 결과가 24px 미만이면
사진 비율을 낮추는 구현안까지 함께 제안해달라.
