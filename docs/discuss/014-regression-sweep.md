## 쟁점

**001~013이 서로 부딪히지 않나.**

열세 스레드가 각자 관문을 남겼고 지금 열 개가 돈다. 그런데 관문 열 개는 각자
**자기가 만든 것**을 본다 — 008은 브리핑, 009는 접힘, 012는 뜨기 모드. 화면
하나를 여러 스레드가 고쳤을 때 그 합이 멀쩡한지는 **아무도 안 본다.**

그리고 앞선 관문은 **전부 한국어 기준**이다. 세는 규칙이 `없어요` 같은
한국어 문구에 걸려 있다. 이 앱의 레이아웃도 한국어 길이에 맞춰 잡혔다 —
`38단 남음`은 짧고 `38 rows left`는 길다. **영어에서 깨지는 자리는 한국어만
재면 절대 안 보인다.**

`WORKLIST.md`의 검증 범위가 "한국어/영어 문구 길이"와 폭 넷을 따로 적은
이유다.

**실기기는 못 쟀다.** 이 환경에는 폰이 없다. 헤드리스에서 safe-area를 CDP로
진짜 값으로 주고(004가 쓰는 방법) 폭 넷을 도는 것까지가 여기서 할 수 있는
전부다 — 남는 것에 적었다.

## 관문 — `scripts/measure-regression.mjs`

폭 넷 × 언어 둘 × 화면 여섯 = **48가지**를 훑는다.

| 관문 | 보는 것                              |
| ---- | ------------------------------------ |
| A    | 가로로 넘치지 않는다                 |
| B    | 글자가 **뜻하지 않게** 잘리지 않는다 |
| C    | 하단 내비가 본문을 가리지 않는다     |
| D    | 결핍 블록이 화면마다 **1개 이하**다  |

**B는 `truncate`를 위반으로 세지 않는다.** 말줄임은 **의도한 자름**이고 이
앱은 목록·카드에서 그걸 쓴다(005·006). 뜻하지 않은 자름은 말줄임 없이 내용이
상자를 넘는 것이다.

**C는 `measure-bottom-nav`와 다른 것을 본다.** 004의 관문은 본문 `padding`과
탭바 높이의 **관계**를 본다. 여기는 화면마다 **마지막 내용이 실제로 탭바 아래
깔리는지**를 본다 — 관계가 맞아도 특정 화면이 `pb-nav`를 안 쓰면 깔린다.

**D는 007의 세는 규칙을 앱 전체로 넓힌 것이다.** 007은 홈에만 걸었고 009가
상세에 0을 요구했는데, 나머지 화면은 아무도 안 봤다.

### 심는 데이터

014의 검증 범위를 그대로 심는다 — 상태 넷(계획중·진행중·잠시멈춤·완성), 사진
있는 것 하나와 없는 것 셋, 실·바늘·게이지·라이프라인·세션. `p0`은 다 갖춘
진행중이고 `p3`은 아무것도 없는 계획중이다. **둘이 이 앱의 양 끝**이라
레이아웃이 깨진다면 거기서 깨진다.

## 처음 돌렸더니 스물두 줄이 빨갰다 — 전부 관문 버그였다

| 잡힌 것                               | 진짜 원인                                                                                                               |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `카드로 공유`가 58px 잘린다 (여섯 번) | 011이 그 라벨을 폰에서 `sr-only`로 내렸다 — **감춘 것이지 잘린 것이 아니다**                                            |
| 데스크톱 다섯 화면이 탭바에 깔린다    | 탭바가 `md:hidden`이라 **없는데**, `display:none`인 요소의 `getBoundingClientRect()`가 전부 0이라 윗변을 0px으로 읽었다 |

**둘 다 앱이 아니라 재는 쪽이 틀렸다.** 고치기 전에 하나씩 왜 그런지 확인한
것이 이 스레드에서 한 일의 절반이다 — 그대로 믿었으면 `sr-only`를 걷어내
011을 되돌리고, 있지도 않은 탭바 때문에 데스크톱 여백을 늘렸을 것이다.

`el.clientWidth <= 1`이면 건너뛰고, 탭바는 **실제로 높이가 있을 때만** 본다.

## 잰 것 — 48가지 전부 0

고친 뒤 48가지 모두 가로 넘침 0px · 뜻하지 않은 잘림 0개 · 탭바 가림 0px ·
결핍 블록 0~1개다. 결핍이 1개인 곳은 **설정 화면 하나**이고 상한 안이다.

| 완료 기준                                 | 어디서 보나                      |
| ----------------------------------------- | -------------------------------- |
| 하단 내비가 본문을 가리지 않는다          | 이 관문 C + `measure-bottom-nav` |
| 첫 화면에서 다음 행동을 바로 안다         | 008 관문 A · 009 관문 A·E        |
| 빈 상태가 차갑거나 숙제처럼 보이지 않는다 | 이 관문 D + 007 · 009 · 013      |
| 테스트·타입·린트·측정 스크립트가 통과한다 | 아래 표                          |

`O4`(머지 뒤 내 커밋이 main에 들어갔는지 보는 자리)는 **018이 이미 닫았다** —
`scripts/finish-work.sh`가 머지 뒤 `git merge-base --is-ancestor`로 확인하고,
일부러 안 들어간 커밋으로 깨뜨려봤다.

보인다.**

## 남는 것

- **실기기를 못 쟀다.** 이 환경에 폰이 없다. 헤드리스 + CDP safe-area가
  004부터 쓰는 대역이고 지금까지 그걸로 잡은 결함이 여럿이지만, 실제 사파리의
  주소창 접힘·홈 인디케이터 제스처·햅틱은 **그 대역 밖**이다. 사람이 한 번은
  손에 들고 봐야 한다.
- **`prefers-reduced-motion`과 큰 글씨 설정을 안 쟀다.** 둘 다 시스템 설정이라
  헤드리스에서 켤 수는 있는데, 켠 뒤 무엇이 맞는지는 아직 아무도 안 정했다.
- **결핍 블록이 설정 화면에 하나 남아 있다.** 상한 안이라 통과하지만, 그게
  007이 말한 "차가운 빈 화면"인지 그냥 사실 한 줄인지는 안 봤다.
