## 쟁점

`docs/DESIGN.md`는 강조색을 쑥 `#3f5d48`로 정했지만, 실제 `src/index.css`는 아직
먹색 계열을 강조색으로 쓴다. 005 검증에서 이 어긋남이 드러났다. **006 홈 첫 카드
시각 개선 전에, 화면이 실제 디자인 토큰으로 보이게 맞출 것인가.**

틀리면 잃는 것: 006부터 013까지의 화면을 잘못된 강조색으로 보고 판단한다. 특히
홈의 큰 `뜨기` 버튼과 `StatusBadge`의 진행중 상태가 문서와 다른 색으로 보이면,
"뜨개 작업대처럼 보이는가"라는 판단이 계속 흔들린다.

## 선택지

**A. 그대로 두고 013에서 한 번에 고친다**
작업 수는 줄어든다. 하지만 013은 새 시각 언어를 정리하는 작업이고, 이 건은 이미
정한 토큰이 코드에 반영되지 않은 문제다. 006~012를 틀린 색으로 검토하게 된다.

**B. 015에서 색 토큰만 맞춘다**
범위가 작고 명확하다. `src/index.css`의 강조 토큰을 `docs/DESIGN.md`와 맞추고,
대비를 다시 재면 된다. 화면 구조나 카드 구성은 건드리지 않는다.

**C. 강조색과 함께 상태색·버튼·카드까지 다시 디자인한다**
한 번에 예뻐질 가능성은 있지만, 015의 본질을 벗어난다. 이건 토큰 drift 수정이지
새 시각 언어 작업이 아니다. 큰 디자인 개편은 013에서 다룬다.

## 대화

### 기획 · 2026-08-29 · 1왕복

**B로 간다.** 브랜치는 `fix/accent-token-drift`로 열었다.

이 작업은 "디자인을 새로 고르는 일"이 아니라 **이미 결정된 디자인 토큰을 코드에
반영하는 일**이다. `docs/DESIGN.md`의 강조 표는 아래처럼 정해져 있다.

| 토큰             | 라이트    | 다크      | 쓰는 곳                      |
| ---------------- | --------- | --------- | ---------------------------- |
| `accent`         | `#3f5d48` | `#86b394` | 주요 버튼, 진행 눈금         |
| `on-accent`      | `#fbfaf9` | `#171615` | 강조 위의 글자               |
| `accent-soft`    | `#edf1ee` | `#22302a` | 라이프라인 칩 같은 흐린 배경 |
| `on-accent-soft` | `#3f5d48` | `#86b394` | 그 위의 글자                 |

그런데 `src/index.css`는 현재 `--accent: #1b1a18`, 다크 `--accent: #eeebe7`이고,
`accent-soft` 계열은 없다. 이 상태로 006 홈 첫 카드를 만들면 큰 `뜨기` 버튼의 색을
잘못 본 채 디자인 판정을 하게 된다.

구현 범위:

| 항목     | 범위                                                                               |
| -------- | ---------------------------------------------------------------------------------- |
| 할 것    | `src/index.css`의 라이트/다크 `--accent`, `--on-accent`를 DESIGN.md 값으로 맞춘다  |
| 할 것    | `--accent-soft`, `--on-accent-soft`와 Tailwind color 매핑을 추가한다               |
| 할 것    | 강조 토큰을 쓰는 주요 위치를 훑고, 색 값 직접 사용이 새로 생기지 않았는지 확인한다 |
| 할 것    | `domain/color.ts`의 `contrastRatio` 또는 동등한 기존 방식으로 대비를 다시 잰다     |
| 안 할 것 | 카드 구조, 홈 첫 카드, 상세 화면, 빈 상태, 넓은 화면 레이아웃 변경                 |
| 안 할 것 | 상태색 전체 재설계. 이번에는 문서에 이미 있는 강조 토큰만 맞춘다                   |

완료 기준:

1. `src/index.css`의 강조 토큰이 `docs/DESIGN.md` 표와 일치한다.
2. `accent-soft`, `on-accent-soft`가 코드에서도 쓸 수 있는 토큰이 된다.
3. 라이트/다크에서 `accent` 위 `on-accent` 대비가 4.5:1 이상임을 수치로 남긴다.
4. 기존 005 카드 구조와 003/004 safe-area 관문을 건드리지 않는다.
5. 최소 `npm run type-check`, `npm run lint`를 통과한다.

내가 다시 반대할 조건: 이 작업에서 "기왕 색 만지는 김에" 버튼 형태, 카드 위계,
상태색 팔레트까지 같이 바꾸는 것이다. 그건 013의 일이다. 015는 006을 올바른 색으로
판정하기 위한 좁은 정렬 작업이어야 한다.

**넘김: 구현** — `src/index.css`의 강조 토큰 drift만 고치고, 대비 수치와 토큰 검색
결과를 남겨달라.

### 구현 · 2026-08-29 · 1왕복

**맞췄다. 그리고 사람이 눈으로 대조하는 방식은 이미 한 번 실패했으므로 기계가
대조하게 했다.**

| 토큰               | 라이트 (전 → 후)          | 다크 (전 → 후)            |
| ------------------ | ------------------------- | ------------------------- |
| `--accent`         | `#1b1a18` → **`#3f5d48`** | `#eeebe7` → **`#86b394`** |
| `--on-accent`      | `#fbfaf9` (그대로)        | `#171615` (그대로)        |
| `--accent-soft`    | **없었음** → `#edf1ee`    | **없었음** → `#22302a`    |
| `--on-accent-soft` | **없었음** → `#3f5d48`    | **없었음** → `#86b394`    |

Tailwind 매핑도 넣었다 — `--color-accent-soft`·`--color-on-accent-soft`.
이제 `bg-accent-soft`·`text-on-accent-soft`가 쓸 수 있는 클래스다.

### 대비 (`domain/color.ts`의 `contrastRatio`)

| 쌍                     | 라이트     | 다크       | 기준  | `DESIGN.md`가 적은 값 |
| ---------------------- | ---------- | ---------- | ----- | --------------------- |
| 강조 ↔ 그 위 글자      | **7.02:1** | **7.65:1** | 4.5:1 | 7.02·7.65             |
| 강조 ↔ 캔버스          | **7.02:1** | **7.65:1** | 4.5:1 | 7.02 / 7.65           |
| 강조 ↔ 카드면          | **7.32:1** | **7.12:1** | 4.5:1 | 7.32                  |
| 흐린 강조 ↔ 그 위 글자 | **6.42:1** | **5.83:1** | 4.5:1 | 6.42                  |
| 흐린 강조 ↔ 카드면     | 1.14:1     | 1.22:1     | —     | —                     |

**문서가 적어둔 값과 한 자리도 다르지 않다.** 문서의 대비 표가 실제로 이 토큰에서
나온 값이었다는 뜻이고, 갈라진 것은 색뿐이었다.

### 잰 값으로 잡은 내 실수 하나

처음에 캔버스를 `#faf9f7`로 넣고 재니 **6.95:1**이 나왔다. `DESIGN.md`는 7.02라고
적고 있어 어긋났다. 문서가 틀린 줄 알았는데 **내가 캔버스 값을 잘못 들고 있었다** —
`src/index.css:19`는 `#fbfaf9`다. 고치니 7.02로 맞는다.

문서에 잰 값이 적혀 있지 않았으면 이 오차를 못 잡았다. 규칙 3이 사는 자리다.

### 테스트로 박았다

`src/domain/design-tokens.test.ts`를 새로 만들었다. 이 어긋남이 생긴 경위가
**"문서만 고치고 코드는 안 고쳤다"**이고, 그걸 사람 눈으로 잡는 데 005까지 걸렸다.
같은 방식을 다시 쓰면 다시 놓친다.

테스트가 지키는 것 넷을 라이트·다크 양쪽에서 본다 — 강조 위 글자 4.5:1, 흐린
강조 위 글자 4.5:1, 강조 ↔ 캔버스 4.5:1, 강조 ↔ 카드면 4.5:1. 10개다.

값을 테스트에 복사해 둔 것은 중복이 아니라 **대조 대상**이다. `index.css`를 고치면
이 테스트가 깨지고, 그때 `DESIGN.md`도 같이 고쳤는지 묻게 된다.

**흐린 강조 ↔ 카드면을 `1~2`로 묶은 것은 내가 고른 기준이다**(규칙 3). 문서에 없다.
라이프라인 칩처럼 깔리는 색이라 너무 세면 카드 위에서 튄다고 봤고, 지금 1.14·1.22다.
근거가 약하면 빼도 된다.

### 색 값을 직접 쓴 자리 — 훑었다

강조 관련 hex를 코드에서 찾으니 셋이 나왔다.

| 자리                                     | 값                   | 판정                                 |
| ---------------------------------------- | -------------------- | ------------------------------------ |
| `src/features/card/render.ts:17`         | `text: "#1b1a18"`    | **drift 아님.** `--text`가 그 값이다 |
| `src/routes/patterns.$patternId.tsx:173` | `ink: "#1b1a18"`     | **drift 아님.** 같은 이유            |
| `src/domain/color.test.ts:47`            | `isLight("#1b1a18")` | 테스트 픽스처                        |

**강조를 직접 쓴 자리는 없었다.** 셋 다 `text` 토큰의 값이고, 이번 작업으로 색이
바뀐 토큰이 아니다. 다만 **토큰 값을 코드에 복사해 둔 것**이라 015가 잡은 것과 같은
종류의 위험은 남는다. 015의 범위가 아니라 손대지 않았다.

### 화면으로 확인

라이트/다크 양쪽에서 계산된 값이 실제로 바뀌었다.

```
light: --accent=#3f5d48  --on-accent=#fbfaf9  --accent-soft=#edf1ee  --on-accent-soft=#3f5d48
dark:  --accent=#86b394  --on-accent=#171615  --accent-soft=#22302a  --on-accent-soft=#86b394
```

하단 내비의 활성 탭과 `새 프로젝트` 버튼이 먹색에서 쑥으로 바뀌었다. `새 프로젝트`
버튼은 44×44에 배경 `rgb(63,93,72)`다.

**스크린샷에서 그 버튼이 안 보여 한 번 놀랐다.** TanStack Query 데브툴 원이
(334,16) 40×40으로 그 위를 덮는다 — 버튼은 (330,20) 44×44다. **검증이 005에서
"클릭이 데브툴 원에 막혔다"고 한 것과 같은 자리**이고, 개발 환경에서만 뜨는
겹침이다. 제품에는 없다.
