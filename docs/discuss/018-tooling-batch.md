## 쟁점

`O1`~`O4`가 쌓였다. 넷 다 **"도구가 제 일을 못 한다"** 하나의 주제이고 각각은
작다. `WORKLIST.md`의 "정비는 배치로 묶는다"대로 007 뒤에 한 브랜치로 처리한다.

**자리 구분이 없어졌다.** 사람이 기획·구현·검증을 나누지 않기로 했으므로 이
스레드는 한 자리가 쓴다. 왕복이 없는 대신 **깨뜨려본 것을 전부 적는다** — 그게
`WORKLIST.md`의 "반복되는 실패 하나"가 요구하는 것이고, 자리가 줄었다고 면제되지
않는다.

## 한 것 넷

### O3 — 훅 둘이 `DESIGN.md`를 루트에서 찾는다

**재현부터 했다.** 팔레트 **안**의 색을 넣어도 "없는 색"이라고 말한다.

| 넣은 색                                | 고치기 전  | 고친 뒤 |
| -------------------------------------- | ---------- | ------- |
| `#fdfcfa` (`docs/DESIGN.md`의 surface) | **경고함** | 조용함  |
| `#3f5d48` (accent)                     | —          | 조용함  |
| `#ff00aa` (팔레트 밖)                  | 경고함     | 경고함  |

고치기 전에는 **둘 다 똑같이 경고**했다. 그러면 이 감시는 신호가 아니라 잡음이고,
015 작업 중 `#fdfcfa`·`#ffffff`가 "DESIGN.md에 없는 색"으로 뜬 것이 그 증거다 —
둘 다 팔레트 안의 색이었다.

**고친 자리가 훅이 아니다.** 완료 기준이 "`omd --force` 재설치 뒤에도 살아남는다"인데,
두 파일 머리에 `omd:installed-hook sha256=…`가 붙어 있어 재설치로 덮인다. 그래서
**저장소 루트에 `DESIGN.md` → `docs/DESIGN.md` 심볼릭 링크**를 뒀다. 훅이 보는
자리에 진짜 파일이 오고, **사본은 생기지 않는다**(015·016이 잡은 것이 사본 사이의
갈라짐이다). OmD는 `.claude/hooks/*`를 갈아치우지 루트 링크를 건드리지 않는다.

`skill-activation` 쪽 오탐도 함께 사라졌다 — UI 프롬프트에서 "DESIGN.md not found
at project root"가 더 안 뜬다.

### O4 — 머지 뒤 내 커밋이 main에 들어갔는지 아무도 안 본다

`finish-work.sh`에 둘을 넣었다. **앞막과 뒷막이 다른 것을 막는다.**

**앞막 — push와 머지 사이의 창**(006에서 찾은 것). `push`가 성공한 뒤 `merge`에
닿기까지의 사이에 누가 같은 브랜치로 push하면, merge가 합치는 것은 **그 사이
갱신되지 않은 로컬 ref**다. main push도 성공해서 어디에서도 실패가 안 난다.

**뒷막 — 머지 뒤 확인**(O4). `origin/$BRANCH`가 `origin/main`의 조상인지 본다.
**로컬 ref를 보면 안 된다** — 머지가 합친 것이 로컬이라 당연히 조상이고, 빠지는
것은 언제나 원격에만 있던 커밋이다.

#### 깨뜨렸다

임시 저장소 둘(원격·내 것·남의 것)을 만들고, **push가 성공한 직후** 남이 같은
브랜치로 push하는 순간을 스크립트 안에 심어 그 창을 정확히 재현했다.

| 무엇                                | 결과                                                                                      |
| ----------------------------------- | ----------------------------------------------------------------------------------------- |
| 앞막 켜고 — push 뒤 남이 끼어듦     | **종료코드 1** · `중단: push한 뒤 origin/feat/x가 움직였습니다` + 잃을 뻔한 커밋 이름     |
| 앞막 끄고(옛 스크립트처럼) — 뒷막만 | **종료코드 1** · `경고: origin/feat/x의 커밋이 origin/main에 안 들어갔습니다` + 커밋 이름 |
| 끼어들기 없이 정상 머지             | **종료코드 0** · `브랜치의 커밋이 전부 origin/main의 조상입니다 (확인함)`                 |

**처음 쓴 O4 코드에 버그가 둘 있었고 돌려보다 찾았다.** 변수 이름을 한글로 둬서
bash가 `command not found`를 냈고, 그 결과 `[ -n "$누락" ]`이 **언제나 참**이라
정상 머지에서도 경고가 떴다. 안 돌려봤으면 "고쳤다"고 적고 넘어갔을 것이다 —
이게 `WORKLIST.md`가 말하는 네 번째 사례다.

### O1 — 하단 내비 관문이 시뮬레이션이다

`measure-bottom-nav.mjs`에서 **클래스 덮기와 `includes("5rem")` 문자열 대조를 둘 다
걷어냈다.** CDP `Emulation.setSafeAreaInsetsOverride`로 진짜 `env()`를 준다(004
검증이 찾아둔 것).

에뮬레이션이 실제로 걸렸는지 먼저 본다 — 안 걸리면 모든 기기가 `env()=0`으로 같은
값을 내며 **조용히 통과**한다. 그때는 관문 실패(1)가 아니라 **환경 문제(2)**로 끝난다.

#### 깨뜨렸다 — 밑값을 양쪽으로 움직여봤다

| `index.css`의 밑값 | 실제로 가리나 | 새 관문 | 옛 관문이라면                           |
| ------------------ | ------------- | ------- | --------------------------------------- |
| `5rem` (지금)      | 안 가림       | **0**   | 통과                                    |
| `3rem`             | **10px 가림** | **1**   | 통과 — **못 잡음**                      |
| `6rem`             | 안 가림       | **0**   | 실패 — 문자열 대조가 `5rem`을 찾다 깨짐 |

**옛 관문은 양쪽으로 틀렸다.** 산술 관문이 `.pb-nav`를 `calc(5rem + …)`로 덮어썼기
때문에 밑값을 줄여도 통과했고, 문자열 대조는 밑값을 고치면 **엉뚱한 이유로** 깨졌다.
지금 관문이 보는 것은 이름도 값도 아닌 **관계**(본문 padding ≥ 탭바 높이)다.

### O2 — 감시자가 다른 브랜치의 스레드를 못 본다

`watch-discuss.sh`가 HEAD의 브랜치 하나만 보던 것을 **모든 원격 브랜치**로 넓혔다.
한 브랜치만 보고 싶으면 `PIN_BRANCH`를 준다.

이 구멍이 실제로 셋을 멈췄다 — 003이 묻혔고, 005가 멈췄고, **007은 사흘 멈췄다.**

**넓히기만 하면 반대쪽으로 시끄러워진다.** 넓히고 처음 돌리니 `004`의 옛
`turn: 기획`이 머지된 브랜치 둘에서 올라왔다. 브랜치는 그때의 사본을 그대로 들고
있어서 **닫힌 차례를 영원히 다시 부른다.** 그래서 둘을 걸렀다.

- **이미 main에 들어간 브랜치는 건너뛴다.** 머지됐다면 그 스레드의 현재 상태는
  main에 있다.
- **main이 이미 닫은 스레드는 다시 부르지 않는다.** main이 기록의 자리이므로,
  거기서 `turn`이 비었으면 끝난 것이다. (머지 안 된 브랜치에 남은 옛 사본이 이
  경우였다.)

#### 깨뜨렸다

**같은 저장소·같은 HEAD(`main`)·같은 순간에 둘을 나란히 돌렸다.** 이 스레드(018)가
`fix/tooling-batch`에만 있고 main에는 없는 상태를 썼다 — O2가 막으려던 바로 그
모양이다.

```
옛 감시자: (아무 말 없음)
새 감시자: 사람 차례입니다 — docs/discuss/018-tooling-batch.md · … (origin/fix/tooling-batch)
```

| 무엇                         | 옛 감시자 | 새 감시자        |
| ---------------------------- | --------- | ---------------- |
| 다른 브랜치의 살아 있는 차례 | **못 봄** | **봄**           |
| 머지된 브랜치의 옛 차례      | 못 봄     | 안 부름 (걸러짐) |
| main이 닫은 스레드의 옛 사본 | 못 봄     | 안 부름 (걸러짐) |
| 워킹 트리의 살아 있는 차례   | 봄        | 봄               |

## 사람이 정할 것

**원격 브랜치 둘이 main에 안 들어간 커밋을 들고 있다.**

| 브랜치                                   | 안 들어간 커밋                                                |
| ---------------------------------------- | ------------------------------------------------------------- |
| `origin/fix/accent-token-drift`          | `e03d3f7` [기획] O3을 앉히고, 세 번 반복된 실패를 이름 붙인다 |
| `origin/fix/mobile-bottom-nav-safe-area` | `a6b38da` [기획] 작업 리스트를 정리한다                       |

**내용은 잃지 않았다** — 둘 다 나중에 다시 쓰여 main에 있다(9/11에 줄 단위로
확인했다). 커밋 객체만 브랜치에 떠 있다.

**사람이 정했다 — 태그로 남기고 브랜치는 지운다.** 그대로 하려다 이
환경에서 막혔고, 그 경위는 아래에 적었다. 원래 물음은 이랬다: 지우면 되돌리기 번거롭고,
남겨두면 O2의 거르기가 매 바퀴 그 둘을 훑는다(지금은 조용하다). 정해주면 따른다.

### 해보고 알았다 — 이 환경에서는 정리가 안 끝난다

사람이 "태그로 남기고 브랜치는 지운다"로 정했다. **그대로 하려다 막혔다.**

| 시도             | 결과                             |
| ---------------- | -------------------------------- |
| 주석 태그 push   | **403**                          |
| 경량 태그 push   | **403**                          |
| 브랜치 삭제 push | **403** — 브랜치가 그대로 남는다 |

이 환경의 git 자격은 **브랜치를 앞으로 미는 것만** 허용한다. 세션 내내 브랜치
push가 됐던 것이 그래서다.

**순서를 지킨 덕에 잃은 것이 없다.** "태그가 origin에 있는 것을 확인한 뒤에만
브랜치를 지운다"로 잡아뒀고, 확인 단계에서 멈췄다. 머지된 브랜치 하나
(`feat/project-image-cards`)로 먼저 시험했는데 그것도 안 지워졌다 — 원격 브랜치
11개와 `main`이 모두 그대로다.

태그 둘(`unmerged/e03d3f7`·`unmerged/a6b38da`)은 **내 로컬에만** 있다. origin에
못 올리므로 컨테이너가 재시작되면 사라진다. **여기서는 보존할 수단이 없다.**

#### 그래서 규칙은 이렇게 남긴다

- **`main`에 안 들어간 커밋을 가진 브랜치는 지우지 않는다.** 지금은 둘이다
  (`fix/accent-token-drift` → `e03d3f7`, `fix/mobile-bottom-nav-safe-area` →
  `a6b38da`). `e03d3f7`은 문서 네 곳에서 여섯 번 **근거로 인용**된다 —
  `WORKLIST.md`의 O4, `006`, `discuss/README.md`, 이 글. 브랜치를 지우면 그
  객체가 원격에서 닿을 수 없게 되고, **근거를 인용해놓고 근거를 지우는 꼴**이 된다.
- **지우려면 먼저 태그로 남긴다.** 태그는 감시자가 안 본다(`refs/remotes/origin`만
  훑는다). 단, **태그 push가 되는 자리에서** 해야 한다.

#### 사람 쪽에서 하면 끝나는 것

로컬 클론이나 GitHub에서. **태그가 올라간 것을 확인한 뒤에만** 지운다.

```
git fetch origin
git tag -a unmerged/e03d3f7 e03d3f7 -m "main에 안 들어간 커밋 — O4의 근거"
git tag -a unmerged/a6b38da a6b38da -m "main에 안 들어간 커밋"
git push origin unmerged/e03d3f7 unmerged/a6b38da
git ls-remote --tags origin          # ← 여기서 둘이 보여야 다음 줄로 간다
git push origin --delete feat/empty-states feat/home-resume-card \
  feat/project-image-cards fix/discuss-watch-branches fix/safe-area-cap \
  fix/token-parity fix/tooling-batch fix/accent-token-drift \
  fix/mobile-bottom-nav-safe-area
```

`claude/continue-work-0m7q16`은 세션의 지정 브랜치라 뺐다.

**안 해도 지금 문제는 없다.** 감시자가 머지된 브랜치를 건너뛰고 main이 닫은
스레드를 다시 안 부르므로 조용하다. 정리는 브랜치 목록을 읽기 쉽게 하는 값이지
기능 문제가 아니다.

## 결정

**O1~O4를 한 배치로 처리했다. 넷 다 깨뜨려보고 먹힌 증거를 함께 적었다.**

| 항목 | 한 것                                                                                            | 깨뜨려 확인                                                    |
| ---- | ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| O3   | 루트에 `docs/DESIGN.md`로 가는 심볼릭 링크 — 훅 파일은 `--force`로 덮이므로 그 밖에 고친다       | 팔레트 안 `#fdfcfa` 조용 · 밖 `#ff00aa` 경고                   |
| O4   | `finish-work.sh`에 **앞막**(push–머지 창)과 **뒷막**(머지 뒤 `origin/$BRANCH`가 main의 조상인가) | 앞막 1 · 뒷막만 1 · 정상 0                                     |
| O1   | `measure-bottom-nav.mjs`에서 클래스 덮기와 `includes("5rem")`을 걷어내고 CDP 실측                | `3rem` → 1(옛 관문은 통과) · `6rem` → 0(옛 관문은 헛되이 실패) |
| O2   | `watch-discuss.sh`가 모든 원격 브랜치를 본다 + 거르기 둘                                         | 같은 HEAD·같은 순간 A/B — 옛 감시자 침묵, 새 감시자 발견       |

**규칙으로 남기는 것**

- **깨뜨렸는데 0이 나오면** 관문이 튼튼한 게 아니라 깨뜨리기가 실패한 것일 수 있다.
  치환이 실제로 걸렸는지를 먼저 본다.
- **`main`에 안 들어간 커밋을 가진 브랜치는 지우지 않는다.** 문서가 그 해시를 근거로
  인용한다. 지우려면 먼저 태그로 남기되, **태그 push가 되는 자리에서** 한다.
- 자동 생성되는 기록(`.omd/`)은 추적 밖에 둔다. 이 저장소의 디자인 기록은
  `docs/DESIGN.md` 하나다.

**안 끝난 것**: 원격 브랜치 정리. 이 환경은 브랜치를 앞으로 미는 것만 허용한다
(태그·삭제 모두 403). 명령은 위에 적어뒀고, **안 해도 지금 동작에는 문제가 없다.**
