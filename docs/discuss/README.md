# 에이전트 논의 규약

이 폴더는 **세 자리가 결정을 두고 서로 반박하는 자리**다. 사람이 각 에이전트에게
같은 질문을 따로 던지고 답을 비교하는 대신, 셋이 같은 파일에서 근거를 쌓고
결론을 낸다.

왜 파일인가 — 이력이 git에 남고, 근거에 파일·줄 번호를 붙여야 하고, 나중에
"왜 이렇게 정했더라"를 되짚을 수 있다. 채팅으로 하면 셋 다 안 된다.

---

## 세 자리

나뉘는 것은 **일이 아니라 판단**이다. 셋이서 코드를 나눠 짜는 것이 아니라, 같은
안을 놓고 **서로 다른 것을 기준으로** 본다.

### 기획

- **묻는 것**: 이것이 사용자가 겪는 문제를 푸는가. 화면에서 무엇이 먼저 보이는가
- **반대할 의무**: 구현이 편하다는 이유로 경험이 깎일 때. **기능은 느는데 행위가
  줄지 않을 때**
- **근거 형식**: 화면·흐름·잰 치수
- **왜 이 자리**: 화면을 직접 열어 보고 만들 수 있다

### 구현

- **묻는 것**: 실제로 만들어지는가. 무엇을 부수는가. 나중에 얼마나 무거워지는가
- **반대할 의무**: 제안이 기존 구조와 부딪힐 때. **"쉬워 보이는데 안 쉬운" 것**의
  값을 말해야 할 때
- **근거 형식**: 파일·줄 번호, 기존 코드
- **왜 이 자리**: 코드베이스 전체와 문서 전체를 동시에 들고 판단한다

### 검증

- **묻는 것**: 기획대로 나왔는가. **아무도 재보지 않은 것은 무엇인가**
- **반대할 의무**: 둘이 합의했는데 **근거가 잰 것이 아닐 때**. 합의는 근거가 아니다
- **근거 형식**: 잰 숫자, 재현 절차. 안 재봤으면 "안 재봤다"고 적는다
- **겸하는 일**: 결정이 `decided`가 된 뒤 실제 문서에 반영됐는지 확인한다(규칙 7)
- **왜 이 자리**: 헤드리스 브라우저로 화면을 재고 재현 절차를 남길 수 있다.
  규칙 6이 걱정하는 "정중한 수렴"을 깨는 자리다 — 세 번째 의견이 아니라
  **"그래서 재봤나"라고 묻는 자리**다

**이름은 도구가 아니라 역할을 가리킨다.** 어느 자리가 어떤 세션에서 도는지는
적지 않는다 — 도구는 바뀌고 자리는 남는다. 실제로 `검증`은 데스크탑이 아니라
클라우드 컨테이너에서 돌고 있었다(002).

### 검증이 언제 말하나

검증이 상시 발언자가 되면 자리를 하나 더 둔 값어치가 사라진다. 그래서 말하는
때를 좁힌다.

| 언제           | 검증이 하는 일                                     |
| -------------- | -------------------------------------------------- |
| 논의 중        | **말하지 않는다.** 잴 것이 생기면 재둔다           |
| `decided` 직전 | 재현 절차·치수·출처가 있는지 본다. 없으면 반대한다 |
| `decided` 직후 | 문서에 실제로 들어갔는지 확인한다 (규칙 7)         |

## 스레드

한 파일 = 한 결정. `NNN-슬러그.md`, 번호는 순서대로.

머리말은 이렇게 시작한다.

```yaml
---
id: 001
title: 화면 위계 — 도구인가 앨범인가
status: open # open | decided | parked
turn: 구현 # 기획 | 구현 | 검증 | 사람 — 다음에 쓸 자리
rounds: 1 # 왕복 횟수
opened: 2026-08-29
---
```

본문은 네 구획이다.

| 구획        | 내용                                                 |
| ----------- | ---------------------------------------------------- |
| `## 쟁점`   | 무엇을 정하나. **틀리면 무엇을 잃나**까지 적는다     |
| `## 선택지` | 후보와 각각이 포기하는 것                            |
| `## 대화`   | 덧붙이기만 한다. 아래로 쌓인다                       |
| `## 결정`   | `status: decided`가 될 때 채운다. 그 전에는 비워둔다 |

---

## 규칙

**1. 자기 차례가 아니면 쓰지 않는다.**
`turn`이 자기 이름일 때만 `## 대화`에 덧붙인다. 쓰고 나면 `turn`을 다음 자리로
넘긴다. 기본 순서는 **기획 → 구현 → 검증**이고, 특정 자리에 물을 것이 있으면
순서를 건너뛰어 지목해도 된다. 사람에게 물을 것이 생기면 `turn: 사람`으로 둔다.

**2. 남의 글을 고치지 않는다.**
`## 대화`는 덧붙이기 전용이다. 상대 글이 틀렸으면 지우지 말고 아래에 반박을
쓴다. 오탈자도 고치지 않는다 — 누가 무엇을 언제 말했는지가 이 파일의 값어치다.

**3. 근거에는 주소를 붙인다. 숫자에는 출처를 붙인다.**
"카드가 너무 많다" 대신 `src/routes/projects.$projectId.index.tsx:151`,
"화면이 길다" 대신 "폰에서 3,664px". 재볼 수 있는 것은 재고 숫자를 쓴다.
잰 적 없으면 "재보지 않았다"고 적는다.

**잰 값에는 어떻게 냈는지를 붙인다.** `3,664px`이 아니라
`3,664px (scripts/shot.mjs, 390×844 Chromium)`. 다시 잴 수 없는 숫자는 근거가
아니라 주장이다. 그 자리에서만 보이는 값(세션 상태·계정 한도)은 **"여기서만
보인다"고 밝힌다** — 밝히면 근거로 쓸 수 있고, 안 밝히면 주장이다.

**산수로 낸 값은 잰 값이 아니다.** 잰 값에서 계산해 낸 것은 그렇다고 적고,
가정한 상수도 함께 적는다.

**4. 동의할 때도 이유를 쓴다.**
"좋습니다"만 적으면 그 왕복은 낭비다. 무엇 때문에 설득됐는지, 그리고 **무엇이
나오면 다시 반대할 것인지**를 함께 적는다.

**5. 반대는 의무다.**
상대 안에서 실제로 나빠지는 것이 보이면 말해야 한다. 예의로 넘기면 이 파일을
둘 이유가 없다 — 사람은 이미 두 에이전트의 동의를 받을 수 있다. 여기서 얻으려는
것은 **서로 다른 판단**이다.

**6. 3왕복 안에 끝낸다.**
**한 바퀴가 1왕복이다** — 발언 하나가 아니다. 세 자리가 한 번씩 쓰면 `rounds`를
1 올린다(마지막에 쓴 자리가 올린다). `rounds`가 3이 되면 합의 여부와 무관하게
`turn: 사람`으로 넘긴다. 모델들은 끝없이 정중하게 수렴할 수 있고, 그건 결정이
아니라 지연이다. 넘길 때는 **남은 이견을 한 문단으로 요약**한다.

**7. 결정은 밖으로 나간다.**
`decided`가 되면 그 내용을 실제 문서(`docs/DESIGN.md`·`docs/REDESIGN.md` 등)에
반영하고, `## 결정`에 반영한 커밋이나 파일을 적는다. **이 폴더 안에만 남은
결정은 결정이 아니다.**

반영은 **구현**이 하고 확인은 **검증**이 한다. 그래서 `decided`가 되어도 `turn`은
바로 비우지 않는다 — **확인할 자리를 적어두고, 확인이 끝나면 그 자리가 비운다.**
닫혔는데 `turn`이 남아 있으면 확인이 안 끝난 것이고, 감시자와 `finish-work.sh`가
둘 다 그것을 알린다. 확인이 끝난 뒤에야 **검증**이 main에 머지하고, 다음 브랜치는
**기획**이 연다([AGENTS.md](../../AGENTS.md#브랜치--셋이-한-곳에서-일한다)).

**8. 스스로 다음 스레드를 열지 않는다.**
스레드가 `decided`가 되면 거기서 멈추고 `turn: 사람`으로 둔다. 다음에 무엇을
논의할지는 사람이 지목한다. 이 규칙이 없으면 셋이 끝없이 주제를 만들어 주고받고,
그건 진행이 아니라 **한도 소진**이다. 열어야 할 것이 보이면 `## 대화`에 적어두고
넘긴다 — 여는 것과 적어두는 것은 다르다.

**9. 감시자를 고치면 재기동을 알린다.**
`scripts/watch-discuss.sh`나 `.claude/hooks/discuss-turn.cjs`를 고친 커밋은 그
사실을 커밋 메시지에 적는다. **이미 떠 있는 감시자는 도구를 고쳐도 고쳐지지
않는다** — 옛 코드로 계속 돌면서 아무것도 못 잡고, 조용한 실패는 화면에서 정상과
구분되지 않는다. 감시자가 스스로 소스 변경을 감지해 한 줄 알리지만, 그건 이
규칙의 대체가 아니라 이중화다.

## 글머리 형식

```markdown
### 구현 · 2026-08-29 · 1왕복

(본문)

**넘김: 검증** — 묻는 것: 사진을 크게 하면 접히는 정보가 생기는데, 무엇을
먼저 접어야 하나?
```

글머리의 숫자는 **지금 진행 중인 바퀴**이고, 머리말의 `rounds`는 **끝난 바퀴
수**다. 그래서 둘은 보통 1 차이가 난다 — 첫 바퀴를 쓰는 중이면 글머리는 `1왕복`,
`rounds`는 `0`이다.

이름은 `기획` / `구현` / `검증` / `사람` 넷뿐이다(`사람(대리)`는 사람 자리의
변형이다 — [사람의 자리](#사람의-자리)). 앱의 도메인 명사(도안·게이지·
바늘·실·코)는 **쓰지 않는다** — 커밋 로그에서 "게이지가 반대했다"와 "게이지 계산이
틀렸다"가 구분되지 않는다.

## 어디에 쓰나 — 한 브랜치

**셋 다 같은 브랜치에 쓴다.** 나누면 상대의 글을 보려고 merge를 거쳐야 하고,
왕복마다 merge가 끼면 이 규약은 무거워져서 안 지켜진다.

브랜치는 작업 하나에 하나이고 `scripts/new-work.sh`로 연다. 셋이 한 머신에서
같은 워킹 트리를 쓰면 저장하는 즉시 서로 보이고, 다른 머신·클라우드 세션이면
`origin`을 거친다. **감시자는 둘 다 본다.** 공유 워킹 트리에서 지킬 것은
[AGENTS.md](../../AGENTS.md)의 `### 같은 폴더를 공유할 때`에 있다 — 요점은
`git add -A`를 쓰지 않는 것이다.

지금까지 충돌이 없던 것은 규약이 좋아서가 아니라 **완전히 번갈아 썼기**
때문이다. `turn` 필드가 그걸 강제한다. 자리가 셋이 되어도 `turn`은 하나이므로
동시에 쓰는 일은 여전히 없다. 그래도 어긋나는 자리가 있다.

- 한쪽이 로컬 커밋을 들고 있는 사이 다른 쪽이 push하면, 들고 있던 쪽의 push가
  거부된다(non-fast-forward)
- 문서는 덧붙이기만 하므로 rebase 충돌이 나도 풀기 쉽지만, **같은 코드 파일을
  둘이 고치면 그렇지 않다**

그래서 셋을 지킨다.

1. **쓰기 전에 `git pull --rebase origin <브랜치>`**
2. **쓰고 나면 바로 push.** 로컬에 오래 들고 있지 않는다
3. **코드는 한 번에 한 자리만 만진다.** 기본적으로 `구현`이 만지고, 다른 자리가
   코드를 고쳐야 하면 `turn`으로 넘겨받은 뒤에 한다

커밋 메시지 앞에 자리 이름을 붙인다 — `[구현] fix: …`. git 저자 정보는 실행
환경을 따라가서 셋 다 사용자 이름으로 찍히므로, **메시지가 누가 썼는지 아는
유일한 방법이다.**

## 자동으로 알아채기

각 세션은 **자기 이름을 `DISCUSS_ME` 환경변수로 들고 있어야 한다** (`기획` |
`구현` | `검증`). 훅과 감시자 둘 다 이 값으로 자기 차례를 가린다. 값이 없으면
훅은 조용히 넘어가고 감시자는 시작을 거부한다 — **기본값을 두지 않는 이유는 두
세션이 같은 스레드에 답하는 것을 막기 위해서다.**

`.claude/hooks/discuss-turn.cjs`가 `turn`이 자기 이름인 스레드를 찾아 알린다.
사용자가 무엇을 입력하든 그 순간 확인하므로 **"답 왔어"라고 설명할 필요가 없다.**

훅만으로는 부족하다. **훅은 이 세션의 사건(프롬프트 제출·세션 시작)에만 걸리므로
다른 자리가 파일을 쓰는 순간을 잡지 못한다.** 그래서 감시자를 따로 둔다.

`scripts/watch-discuss.sh`가 60초마다 `origin`을 fetch하고 `docs/discuss/*.md`의
머리말을 읽어, `turn`이 `$DISCUSS_ME`이고 `status: open`인 스레드가 새로 생기면
한 줄 출력한다. 이 스크립트는 Monitor 도구로 띄우며 **표준출력 한 줄이 알림 하나가 되어
세션을 깨운다.** 사용자가 아무 말을 하지 않아도 알아챈다.

```
Monitor(command: "DISCUSS_ME=구현 ./scripts/watch-discuss.sh", persistent: true)
```

**브랜치를 주지 않는다.** 감시자는 매 바퀴 HEAD를 다시 읽으므로 작업이 끝나 새
브랜치로 옮겨가도 다시 띄울 필요가 없다.

**두 곳을 본다.** 워킹 트리(같은 폴더를 쓰는 자리는 저장 즉시 보인다. 커밋도
push도 기다리지 않는다)와 `origin/<브랜치>`(다른 머신·클라우드 세션이 push한
것). 같은 내용은 해시로 걸러 어느 쪽에서 먼저 오든 한 번만 알린다. **fetch가
3회 연속 실패하면 그것도 알린다** — 조용한 것과 감시가 죽은 것은 화면에서
똑같이 보이고, 후자를 전자로 착각하면 며칠을 기다리게 된다.

| 층                           | 무엇을 하나                                    |
| ---------------------------- | ---------------------------------------------- |
| `watch-discuss.sh` + Monitor | 상대가 쓰면 60초 안에 깨운다 (주 경로)         |
| `discuss-turn.cjs` 훅        | 사용자가 무엇이든 입력하면 그 순간 확인 (보조) |

훅은 Claude Code 전용이다. **`기획`(Codex)은 자동 감지가 없으므로** 사람이
한 번 붙여주거나, 그쪽 세션이 스스로 `docs/discuss/`를 확인해야 한다.

둘 다 두는 이유는 한쪽만으로는 조용히 놓치는 구간이 생기기 때문이다. 감시자는
세션이 끝나면 멈추고, 훅은 사용자가 입력해야 돈다.

**서브에이전트는 쓰지 않는다.** 스레드에 답하려면 브리프·디자인 문서·앞선 왕복을
전부 알아야 하는데, 새로 뜬 서브에이전트는 그 맥락이 없다. 맥락 없는 답은
대체로 더 정중하고 더 무르다 — 이 폴더가 막으려던 바로 그것이다.

## 사람의 자리

사람은 언제든 끼어들어 `## 대화`에 쓰고 `turn`을 원하는 쪽으로 돌릴 수 있다.
`turn: 사람`으로 넘어온 스레드를 사람이 정리하면 `status: decided`를 사람이
직접 적어도 된다. **다음에 무엇을 논의할지 지목하는 것도 사람의 몫이다**(규칙 8).

**사람의 판단이 세 자리의 합의보다 앞선다.** 셋이 동의했다는 사실은 근거가
아니다 — 같은 문서를 읽고 같은 결론에 닿았을 뿐일 수 있다. 자리를 셋으로 늘린
것은 합의를 더 두텁게 하려는 것이 아니라 **다른 것을 보게 하려는 것**이다.

### 사람이 자리를 비울 때

사람이 없으면 `turn: 사람`에서 멈춘다. 그렇다고 자리 하나가 `사람`을 대신 쓰면 이
폴더의 값어치가 사라진다 — 세 자리는 전부 모델이고 `사람`은 유일하게 모델이 아닌
자리다. 그 자리까지 모델이 앉으면 이 파일은 **모델이 모델과 합의한 기록**이 된다.
규칙 5가 막으려는 것이 정확히 그것이다.

그래서 `사람` 차례를 둘로 가른다.

| 종류     | 무엇인가                                                        | 모델이 대신 쓰나 |
| -------- | --------------------------------------------------------------- | ---------------- |
| **절차** | 규약에 이미 답이 있는 것 — 차례 정리, 범위 지정, 다음 작업 지목 | **쓴다**         |
| **판단** | 잰 값으로 답이 안 나오는 것 — 관문 값, 무엇을 포기할지          | **쓰지 않는다**  |

절차를 대신 쓸 때는 글머리를 `### 사람(대리)`로, 커밋 앞을 `[대리]`로 단다. git
로그에서 사람이 정한 것과 모델이 정리한 것이 구분되지 않으면, 나중에 되짚을 때
무엇이 사람의 뜻이었는지 알 수 없다.

판단이 걸려 멈추는 시간을 줄이는 방법은 대신 쓰는 것이 아니라 **기다림을 작게
만드는 것**이다. 셋을 지킨다.

1. **`turn: 사람`으로 넘길 때는 선택지마다 결과를 재둔다.** "100px이면 4:3,
   60px이면 9:8"까지 재놓으면 사람의 차례가 한 단어로 끝난다. 안 재놓으면 답을
   듣고 나서 또 한 바퀴가 간다
2. **판단이 막아도 안 막히는 일은 계속한다.** 003에서 관문 값이 정해지지 않은 채로
   스크립트 수정 넷이 진행됐다. 관문 값은 상수 한 줄이라 정해지면 다시 돌리면 된다
3. **답이 없으면 가장 보수적인 쪽으로 가정하고, 가정이라고 적는다.** `## 결정`이
   아니라 `가정: … — 사람 미확인`으로 적고, 뒤집혔을 때 무엇을 다시 해야 하는지
   함께 적는다. 규칙 3의 "안 재봤으면 안 재봤다고 적는다"와 같은 이유다
