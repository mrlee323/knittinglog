# 배색 차트 에디터 — 사양

- 문서 상태: v1 (2026-08-20)
- 대상 화면: `/charts/:id` (`src/routes/charts.$chartId.tsx`)
- 관련 도메인: `domain/colorChart.ts` · `domain/fabric.ts` · `domain/color.ts`

---

## 1. 무엇을 만드는가

**뜨개 도안을 작성하는 도구**다. 픽셀 아트 편집기가 아니다.

이 구분이 도구 선택을 정한다. 픽셀 편집기의 기능 목록(레이어·자유 브러시·회전·
그라디언트)을 따라가면 화면만 복잡해지고, 정작 뜨개에서 실패하는 지점은 하나도
막지 못한다. 반대로 뜨개에만 있는 제약(뒷실 길이, 명도 대비, 반복 정합, 읽는
방향)은 어느 편집기도 모른다. **거기가 우리 자리다.**

참고 대상(Colorwork Studio)과 겹치는 부분은 겹치되, 그 도구가 구조적으로 못
가진 것 — 사용자의 스태시, 사용자의 프로젝트, 카운터 — 으로 벌린다.

## 2. 지금 있는 것 / 없는 것

**있는 것**

| 기능                  | 구현                                               |
| --------------------- | -------------------------------------------------- |
| 드래그로 연속 칠하기  | `chart-canvas.tsx` (pointerdown → move)            |
| 팔레트 (색 추가·변경) | 화면 상단, 색은 스태시 실 색과 별개로 자유 입력    |
| 격자 크기 변경        | `resizeChart` — 끝에서 자라거나 잘린다             |
| 전체 좌우 반전        | `mirrorChart`                                      |
| 사진 → 차트           | `imageToChart` (색 양자화 + 스태시 실 색 맞추기)   |
| 천 미리보기           | `fabric.ts` — 반복 타일링 · 게이지 비율 · 줌 3단계 |
| 단별 읽기             | `rowRuns` — "회색 3, 겨자 2, 회색 5"               |

**없는 것** — 3·4절이 끝났으므로 이제 5절이 이 목록이다.

## 3. 1차 — 없으면 에디터가 아닌 것 ✅ 구현됨

### 3.1 되돌리기 · 다시하기

**한 획을 한 단위로 묶는다.** 칸 하나를 스택에 쌓으면 드래그로 40칸을 칠한 뒤
되돌리기를 40번 눌러야 한다. `pointerdown`에서 스냅샷을 찍고 `pointerup`에서
확정한다.

차트는 `width × height` 정수 배열이라 스냅샷이 싸다(20×20이면 400바이트).
따라서 diff를 만들 이유가 없다 — **전체 스냅샷 50단계**를 배열로 들고 있는다.
50단계면 한 세션에서 되돌릴 만큼이고 20KB를 넘지 않는다.

되돌리기 대상: 칠하기 · 채우기 · 대칭 칠하기 · 삽입/삭제 · 색 일괄 교체 ·
사진에서 가져오기. 팔레트 색 변경도 포함한다 — 색을 잘못 바꾸면 도안 전체가
바뀌므로 되돌릴 수 있어야 한다.

자동 저장(400ms 지연)과 순서가 엮인다. **되돌린 결과도 저장돼야 한다** —
되돌리고 나갔다가 돌아왔을 때 되돌리기 전 상태가 남아 있으면 안 된다.

### 3.2 채우기

같은 색이 이어진 영역을 현재 색으로 바꾼다. 4방향(상하좌우) 연결만 본다 —
대각선까지 이으면 배색 무늬에서 의도하지 않은 영역까지 번진다.

경계는 차트 밖이다. **반복 경계를 넘어 번지지 않는다** — 반복은 표시일 뿐이고
데이터는 한 장이다.

### 3.3 스포이드

탭한 칸의 색을 현재 색으로 집는다. 팔레트에 없는 색은 없으므로 인덱스만
바꾸면 된다. 배색은 색 두세 개를 왕복하며 칠하는 작업이라, 팔레트로 손을
옮기는 왕복을 줄이는 게 목적이다.

**1차 완료 기준**: 20×20 도안을 처음부터 끝까지 그리는 동안 팔레트 왕복과
오탭 복구가 손을 멈추지 않는다.

**구현 결과** — 도구 셋(칠하기·채우기·색 집기)과 되돌리기·다시하기가 들어갔다.
확인한 것: 한 획으로 칠한 4칸이 되돌리기 한 번에 돌아간다, 채우기는 이어진
영역만 바꾸고(70칸 중 20칸) 되돌리기 한 번에 복구된다, 색을 집으면 곧바로
칠하기로 돌아온다. `Cmd/Ctrl+Z`와 `Shift`도 붙였다 — 기준 화면이 PC다.

색 집기 뒤에 칠하기로 자동 복귀하는 것은 의도다. 색을 집는 이유는 그 색으로
칠하려는 것이고, 도구를 두 번 바꾸게 하면 왕복을 줄인 의미가 없다.

## 4. 2차 — 여기서 갈라진다 ✅ 구현됨

**구현 결과** — 셋을 함께 넣었다. 도구는 하나(대칭 그리기)뿐이고 둘은 아무것도
하지 않는 것(뒷실·명도 경고)인데, 실제로 도안을 살리는 쪽은 후자였다. 12×12에
대각선 하나를 그으니 뒷실 12곳이 잡혔고, 빨강과 초록을 나란히 놓으면 명도비가
1.0:1로 나온다 — 흑백으로 보기를 켜면 무늬가 통째로 사라진다.

### 4.1 대칭 그리기

세로축 대칭 토글. 켜면 칠할 때마다 좌우 반대 칸이 함께 칠해진다.

배색·레이스 무늬의 대부분이 좌우 대칭이라 **작업량이 절반**이 된다. 지금 있는
`mirrorChart`(전체 뒤집기)와는 다른 기능이다.

폭이 홀수면 가운데 열은 자기 자신이 짝이므로 한 번만 칠한다. 가로축(위아래)
대칭은 넣지 않는다 — 뜨개 무늬에서 위아래 대칭은 드물고, 토글이 둘이면 어느
쪽이 켜졌는지 헷갈린다.

**켠 상태를 저장하지 않는다.** 대칭은 도안의 성질이 아니라 지금 손의 방식이다 —
대칭인 무늬도 마무리는 한쪽만 손보게 된다. 반대로 원형/평면과 뒷실 기준(4.2)은
도안 자체의 성질이라 레코드에 남긴다. 인덱스를 걸지 않은 필드라
스키마 변경은 없다.

### 4.2 뒷실(부동사) 경고 — **아무 도구도 하지 않는 것**

페어아일에서 같은 색이 여러 코 연속되면 그 뒤로 다른 색 실이 길게 지나간다.
그 실이 길면 손가락에 걸리고 편물이 당긴다. 초보가 가장 자주 망치는 지점이고,
**다 뜨고 뒤집어 봐야** 안다.

- 기준: 기본 5코. 3~9코로 조절 가능(실 굵기와 취향에 따라 다르다).
- 계산: `rowRuns`를 그대로 쓴다. 단마다 연속 구간을 세고 기준을 넘는 구간을 모은다.
- **원형은 단의 끝과 시작이 이어진다.** 마지막 구간과 첫 구간이 같은 색이면
  하나로 합쳐 센다. 평면은 합치지 않는다. 이 구분을 놓치면 원형 도안에서
  가장 긴 뒷실을 놓친다.
- 표시: 해당 구간에 사선 해칭을 덮고, 요약으로 "뒷실 3곳 · 가장 긴 것 8코".
  경고는 빨강을 쓰지 않는다 — 틀린 게 아니라 알고 하면 되는 선택이다
  (`hibernating` 색을 쓴다, `docs/DESIGN.md` §2). 색이 아니라 **해칭**이어야 하는
  이유가 하나 더 있다: 팔레트는 사용자의 색이라 어떤 경고색을 골라도 어느
  도안에서는 배색과 구분되지 않는다.
- **한 색뿐인 단은 세지 않는다.** 그 단은 실을 하나만 들고 뜨므로 뒤로 지나갈
  실이 없다. 이걸 빼지 않으면 배경만 있는 단이 전부 경고로 잡혀서 정작 봐야 할
  구간이 묻힌다 — 기준을 넘는 구간을 모으는 계산만으로는 놓치는 지점이다.

### 4.3 명도 대비 경고

색이 달라도 **명도가 비슷하면 무늬가 사라진다.** 배색은 두 색이 인접해야 무늬가
되므로, 팔레트의 모든 색 조합을 검사한다.

- 상대휘도(WCAG)로 명도차를 계산한다. 색상(hue) 차이는 보지 않는다 — 빨강과
  초록은 색상이 정반대지만 명도가 같으면 사진에서 뭉친다.
- 임계값은 경험값으로 정하고 문서에 남긴다(초안: 휘도비 1.5:1 미만이면 경고).
  글자 가독성 기준(4.5:1)을 쓰면 안 된다 — 배색은 글자가 아니라 면이라 그보다
  훨씬 낮은 차이에서도 무늬가 읽힌다.
- 흑백 보기 토글을 함께 준다. 경고 문장보다 눈으로 보는 게 빠르다. 팔레트만
  회색으로 바꿔 같은 데이터를 그린다 — 보기 모드가 저장되는 색을 바꾸면 안 된다.
- `color.ts`에 `isLight`가 이미 있지만 그걸 쓰지 않는다. 쓰임이 다르다 —
  `isLight`는 **글자를 이 색 위에 얹을지**를 감마 있는 근사식으로 정하고,
  이쪽은 **두 색이 나란히 놓였을 때 구분되는지**를 잰다. 후자는 감마를 벗겨야
  맞다.

## 5. 3차 — 정리와 편의

### 5.1 반복 안내선

도안은 10코마다 굵은 선을 넣는 관습이 있다. 그 위에 **반복 단위**(코수·단수)를
지정하면 경계를 강조한다. 무늬가 이어질 때 어긋나는 걸 그리는 중에 알 수 있다.

프로젝트에서 열었으면 그 프로젝트의 코수와 맞는지도 말해준다 — "몸판 118코에
10코 무늬면 11.8회, 8코 남음". `construction.ts`의 반복 검산을 재사용한다.

### 5.2 단·코 삽입 / 삭제

지금은 크기 입력으로만 늘어나고 끝에서 자란다. 중간에 한 단을 끼워넣는 게 실제
작업이므로 위치를 지정해 삽입·삭제한다. `resizeChart`와 별도 함수로 둔다.

### 5.3 색 일괄 교체

팔레트의 어떤 색을 다른 색으로 바꾼다(셀 재매핑). 스태시 실이 모자랄 때 색을
갈아치우는 작업이라 실 부족 경고와 이어진다.

### 5.4 직선 · 사각형

3차로 미룬다. 대칭 그리기가 들어오면 손이 훨씬 덜 아프고, 배색 무늬는 대개
곡선이라 직선 도구의 쓸모가 생각보다 작다.

## 6. 도메인에 들어갈 순수 함수

에디터의 판단은 전부 순수 함수로 빼고 테스트한다. UI에서 계산하면 "왜 여기가
경고인지"를 나중에 아무도 확인할 수 없다.

| 함수                                            | 하는 일                             |
| ----------------------------------------------- | ----------------------------------- |
| `fillArea(chart, x, y, color)`                  | 4방향 채우기                        |
| `mirrorCell(chart, x)`                          | 대칭 좌표. 홀수 폭의 가운데 열 처리 |
| `longFloats(chart, { threshold, inRound })`     | 기준을 넘는 뒷실 구간               |
| `contrastWarnings(palette, threshold)`          | 명도차가 부족한 색 조합             |
| `relativeLuminance(hex)` · `contrastRatio(a,b)` | WCAG 명도 (`color.ts`)              |
| `toGray(hex)`                                   | 휘도를 유지한 회색 (`color.ts`)     |
| `insertRow/removeRow/insertColumn/removeColumn` | 위치 지정 삽입·삭제                 |
| `remapColor(chart, from, to)`                   | 색 일괄 교체                        |

## 7. 안 하기로 한 것

- **레이어** — 도안은 한 장이다. 레이어를 두면 저장 형식이 복잡해지고 "합치기"
  라는 개념을 사용자에게 가르쳐야 한다.
- **자유 브러시 크기** — 코는 이산적이다. 2코 브러시는 격자를 두 칸씩 칠하는
  것이고, 그건 드래그로 이미 된다.
- **회전** — 배색 무늬를 90도 돌리면 코와 단이 바뀌어 게이지 비율이 뒤집힌다.
  뜨개에서 성립하지 않는 조작이다.
- **무한 캔버스 / 팬 줌** — 도안은 정해진 코수 안에서 그린다. 크기 변경으로
  충분하다.

## 8. 남은 질문

- 뒷실 기준의 기본값은 5코로 두지만, 실 굵기에 따라 달라진다. 스태시의 굵기를
  알면 자동으로 조절할 수 있는데(굵은 실은 더 짧게) 그게 과한 친절인지 판단이 필요하다.
  지금은 도안마다 3~9코로 직접 고른다.
- 명도 대비 임계값은 경험값이다. 실제 편물 사진과 비교해 보정해야 한다.
- 팔레트에 넣었지만 아직 쓰지 않은 색도 명도 검사에 들어간다. 지금은 그게 맞다고
  본다 — 어느 색이 어디에 인접할지는 그리는 중에 계속 바뀌므로, 지금 붙어 있지
  않다고 안심시키는 건 도움이 되지 않는다.

**정해진 것**

- 대칭 그리기를 켠 상태의 채우기는 **반대쪽 씨앗에서 한 번 더 채운다.** 영역을
  뒤집어 옮기는 것이 아니다. 같은 조작을 반대쪽에 한 번 더 하는 것이라 비대칭
  영역에서도 결과를 예상할 수 있고, 두 영역의 모양이 다를 때 한쪽이 뭉개지지
  않는다. 되돌리기는 한 단위다.
