## 핵심 방향

**기능을 더 많이 보여주는 것이 아니라, 사용자가 자기 작품을 더 예쁘고 정확하게
기억한다고 느끼게 한다.**

뜨개를 하는 사람은 실 색, 작품 사진, 기록의 질감을 중요하게 본다. 그래서 우리
앱의 UI는 생산성 도구처럼 차갑게 정리되기보다, "다시 열고 싶은 뜨개 작업대"처럼
보여야 한다.

지켜야 할 기준:

- 작품 사진과 실 색이 주인공이다.
- 앱의 브랜드 색은 작품과 경쟁하지 않는다.
- 첫 화면은 통계보다 "이어서 뜰 작품"을 먼저 보여준다.
- 빈 상태는 결핍 목록이 아니라 시작을 돕는 예쁜 안내여야 한다.
- 뜨는 중 화면은 감성보다 정확성, 큰 터치, 오조작 방지가 우선이다.
- 폰 안전영역과 하단 내비 겹침은 모든 카드 작업보다 먼저 안전해야 한다.

## 005 — 프로젝트 목록 카드 이미지형 전환

### 왜 먼저 하나

`REDESIGN.md` 1단계의 첫 작업이다. 사용자가 "뜨개하는 사람들은 이쁜 걸 좋아한다"고
말한 방향에 가장 직접적으로 닿는다. 지금 프로젝트 목록은 관리 리스트에 가깝고,
작품 사진이 오른쪽 작은 썸네일로만 존재한다.

목표는 **프로젝트 목록을 관리표가 아니라 작은 작품 갤러리처럼 보이게 하는 것**이다.

### 기획/디자인 방향

- 사진이 있는 프로젝트는 카드 상단 또는 큰 영역에 대표 사진을 둔다.
- 사진 비율은 폰에서 `aspect-[4/3]`을 넘기지 않는다.
- 사진 위에 글자를 얹지 않는다. 편물 색과 가독성이 싸운다.
- 프로젝트명, 상태, 현재 단수/카테고리는 사진 아래에 둔다.
- 실 색은 기존 3px 세로선보다 조금 더 존재감 있게, 스와치 바나 작은 칩 묶음으로
  보여준다.
- 사진이 없는 프로젝트는 회색 박스가 아니라 실 색/카테고리 기반의 조용한 패턴이나
  블록으로 대체한다.
- 필터 칩은 유지하되, 카드보다 시각적으로 세지 않게 낮춘다.

### 구현에게 넘길 범위

- 대상 화면: 프로젝트 목록
- 우선 파일 후보: `src/routes/projects.index.tsx`
- 할 것: 카드 구조, 사진 영역, 스와치 표현, 빈 사진 fallback
- 안 할 것: 홈 첫 카드, 프로젝트 상세, 뜨기 모드

### 완료 기준

- 폰에서 목록 카드가 사진 중심으로 읽힌다.
- 사진이 없어도 카드가 "빈 회색 박스"처럼 보이지 않는다.
- `aspect-[4/3]` 상한을 지킨다.
- 기존 필터와 프로젝트 이동 동선이 깨지지 않는다.
- 003/004 측정 관문을 다시 돌렸을 때 safe-area 문제가 재발하지 않는다.

## 006 — 홈 첫 카드 시각 개선

### 목표

앱을 열자마자 "내 작품으로 돌아왔다"는 느낌을 준다. 홈 첫 카드는 통계 요약이 아니라
**이어서 뜨기 카드**여야 한다.

### 기획/디자인 방향

- 첫 카드 이름은 "이어서 뜨기"로 둔다.
- 대표 사진, 프로젝트명, 현재 단수, 진행률, 마지막 작업 시점, 큰 `뜨기` 버튼을 둔다.
- 사진은 폰에서 `aspect-[4/3]` 이하로 제한한다.
- `뜨기` 버튼은 카드 안에서 가장 강한 조작이어야 한다.
- 통계 타일은 첫 카드보다 작고 조용하게 둔다.

### 완료 기준

- 첫 화면에서 사용자가 눌러야 할 것이 `뜨기` 하나로 선명하다.
- 두 번째 카드/프로젝트가 폰 safe-area 조건에서도 일부 보인다.
- 계획중 프로젝트도 홈에서 사라지지 않는다.

## 007 — 빈 상태/온보딩 개선

### 목표

아무 데이터가 없어도 앱이 예쁘고 친절해 보여야 한다. 빈 상태가 "없어요" 목록처럼
쌓이면 사용자는 숙제를 받은 느낌을 받는다.

### 기획/디자인 방향

- 홈 빈 상태는 샘플 카드 1개와 `새 프로젝트` CTA로 구성한다.
- "작품명만 적고 시작해도 돼요"처럼 부담을 낮춘다.
- 첫 프로젝트 생성 뒤 사진, 실, 카운터 추가를 한 번에 강요하지 않는다.
- 빈 섹션 여러 개를 한 화면에 반복하지 않는다.

### 완료 기준

- 첫 사용자에게 앱의 최종 모습을 상상하게 한다.
- 입력해야 할 것이 많다는 압박을 줄인다.
- 빈 상태 문구가 죄책감이나 결핍으로 읽히지 않는다.

## 008 — 프로젝트 상세 상단 복귀 브리핑

### 목표

프로젝트를 다시 열었을 때 5초 안에 "어디서 이어 뜨면 되는지" 알게 한다.

### 기획/디자인 방향

- 상세 상단에 복귀 브리핑 영역을 만든다.
- 포함 정보: 마지막 작업일, 현재 단수, 남은 단수, 마지막 lifeline, 연결된 도안/자료,
  실 잔량, 바늘.
- 대표 사진 또는 최근 사진을 상단에서 크게 보여준다.
- `뜨기 모드로 가기`는 항상 눈에 잘 보여야 한다.
- 문구는 "오래 멈췄어요"보다 "여기서 이어갈 수 있어요" 쪽으로 쓴다.

### 완료 기준

- `뜨기` 버튼까지 스크롤이 없어야 한다.
- 상세 첫 화면의 주인공이 복귀 브리핑과 이어뜨기 동선으로 보인다.
- 수정/삭제/복제 같은 관리 동작은 주동선보다 약하게 배치된다.

## 009 — 프로젝트 상세 빈 섹션 접기

### 목표

상세 화면의 길이를 줄인다. 빈 프로젝트에서 "없어요"가 여러 번 반복되는 문제를
없앤다.

### 기획/디자인 방향

- 조각, 카운터, 게이지, 실, 바늘 섹션은 비어 있으면 접는다.
- 채우는 길은 섹션마다 흩어진 `+` 버튼 대신 한 자리에서 제안한다.
- 시작 안내 카드가 빈 프로젝트의 유일한 안내가 되게 한다.
- `수정`, `삭제`, `이대로 다시 뜨기`는 본문에서 빼고 상단 메뉴로 보낸다.

### 완료 기준

- 빈 프로젝트 상세 높이를 큰 폭으로 줄인다.
- "뜨기" 동선이 첫 화면에 들어온다.
- 없는 정보가 아니라 가진 정보가 먼저 보인다.

## 010 — 타이포·숫자 위계 정리

### 목표

색을 많이 쓰지 않는 대신 크기, 굵기, 여백, 숫자 위계로 화면의 목소리를 만든다.

### 기획/디자인 방향

- 단수, 남은 단, 실 잔량, 게이지 같은 숫자는 본문보다 한 단계 이상 크게 둔다.
- 섹션 제목, 카드 제목, 보조 설명의 스케일을 분명히 나눈다.
- 한글 제목에는 `word-break: keep-all`을 적용한다.
- 숫자는 탭уляр/고정폭 느낌을 검토해 흔들림을 줄인다.

### 완료 기준

- 중요한 숫자가 한눈에 보인다.
- 제목이 단어 중간에서 어색하게 끊기지 않는다.
- 화면 전체가 같은 크기의 회색 텍스트 묶음처럼 보이지 않는다.

## 011 — 넓은 화면 레이아웃 개선

### 목표

태블릿과 PC에서 폰 레이아웃을 가운데 둔 것처럼 보이지 않게 한다.

### 기획/디자인 방향

- 프로젝트/실/게이지 목록은 `md` 2열, `xl` 3열 격자를 검토한다.
- 홈은 데이터와 작업 카드의 비율을 다시 잡는다.
- 프로젝트 상세는 보는 것과 조작하는 것을 2단으로 나눈다.
- 죽은 가로 여백을 줄이되, 작품 사진이 답답해지지 않게 한다.

### 완료 기준

- 1280px 화면에서 오른쪽이 비어 보이지 않는다.
- 목록형 화면이 넓은 화면에서 정보 밀도를 자연스럽게 올린다.
- 폰 레이아웃은 깨지지 않는다.

## 012 — 뜨기 모드 폴리싱

### 목표

실제로 뜨는 순간에는 실수하지 않게 한다. 예쁨보다 정확성, 큰 터치, 현재 위치
복원이 우선이다.

### 기획/디자인 방향

- 현재 단수 숫자를 화면 높이 기준으로 더 키운다.
- `+1` 영역은 빈 회색 상자가 아니라 명확히 누르는 면으로 보이게 한다.
- 도안이 없으면 안내문이 화면 절반을 차지하지 않게 한다.
- 되돌리기, lifeline, 화면 꺼짐 방지는 접근하기 쉬워야 한다.
- 폰은 카운터 우선, 태블릿 이상은 도안+카운터 병렬을 검토한다.

### 완료 기준

- 폰에서 현재 단수와 `+1`이 가장 먼저 보인다.
- 도안이 없는 상태가 결핍처럼 보이지 않는다.
- 오조작 방지와 되돌리기 동선이 유지된다.

## 013 — 새 시각 언어 정리

### 목표

구조 개선 뒤, 뜨개앱다운 새 옷을 입힌다. 구조와 시각 언어를 한 커밋에 섞지 않는다.

### 후보 방향

| 방향 | 분위기                                  | 적합한 사용자                           |
| ---- | --------------------------------------- | --------------------------------------- |
| 계기 | 게이지자, 저울, 눈금, 정확성            | 계산 엔진을 신뢰하는 중급자             |
| 염색 | 쪽빛, 생지, 천연염색, 작품 사진         | 완성작과 실 색을 자랑하고 싶은 사용자   |
| 니트 | 메리야스 조직, 부드러운 반복, 초보 친화 | 자주 멈추지만 다시 시작하고 싶은 사용자 |

### 기획/디자인 방향

- 새 색을 많이 칠하기보다 질감, 비례, 여백, 사진 처리로 뜨개다움을 만든다.
- 앱 UI 색은 작품 사진과 실 색을 이기지 않는다.
- 카드 반경, 그림자, 배경 질감, 스와치 표현을 한 번에 정리한다.
- 결정되면 [DESIGN.md](DESIGN.md)에 반영한다.

### 완료 기준

- 화면이 생산성 도구가 아니라 뜨개 작업대처럼 보인다.
- 사진이 없어도 화면이 밋밋하지 않다.
- 디자인 토큰과 실제 컴포넌트가 서로 어긋나지 않는다.

## 014 — 실기기/전체 회귀 검증

### 목표

001~013의 변화가 실제 사용 흐름에서 서로 부딪히지 않는지 확인한다.

### 검증 범위

- 모바일 safe-area: 홈, 목록, 상세, 설정, 뜨기 모드
- 프로젝트 생성 후 홈/목록/상세 이동
- 사진 있는 프로젝트와 사진 없는 프로젝트
- 계획중, 진행중, 잠시멈춤, 완성 상태
- 한국어/영어 문구 길이
- 375×812, 390×844, 430×932, 1280px 이상

### 완료 기준

- 주요 화면에서 하단 내비가 본문을 가리지 않는다.
- 첫 화면에서 사용자가 다음 행동을 바로 알 수 있다.
- 빈 상태가 차갑거나 숙제처럼 보이지 않는다.
- `npm run test`, `npm run type-check`, `npm run lint`, 필요한 화면 측정 스크립트가
  통과한다.

## 운영 작업

제품 UI 작업과 섞지 말고 별도 작업으로 다룬다.

### O1 — 하단 내비 측정 관문 개선

004에서 검증이 남긴 후속 작업이다. `scripts/measure-bottom-nav.mjs`의 클래스 덮기와
`includes("5rem")` 문자열 대조를 줄이고, CDP `Emulation.setSafeAreaInsetsOverride`
기반 실측으로 단순화한다.

이 작업은 사용자 화면을 바꾸지 않으므로, 005 카드 작업과 섞지 않는다.

### O2 — 감시자가 다른 브랜치 스레드를 못 보는 문제

004에서 뒤로 미룬 운영 문제다. 현재 감시자는 HEAD 기준 브랜치만 본다. 새 작업
브랜치가 열렸을 때 다른 세션이 자동으로 알아채지 못할 수 있다.

이 작업은 중요하지만, 사용자가 보는 뜨개앱 화면 개선과 분리한다.

---

## Codex가 다음 차례에 할 일

1. 004가 main에 머지됐는지 확인한다.
2. main이 최신이면 005 스레드를 열고 `./scripts/new-work.sh <브랜치>`로 새 브랜치를
   만든다.
3. 005에서는 프로젝트 목록 카드만 다룬다. 홈 첫 카드나 상세 화면을 섞지 않는다.
4. 논의 파일에는 구현이 바로 읽을 수 있게 디자인 방향, 범위, 완료 기준, 반대 조건을
   쓴다.
5. 구현/검증 차례에는 감시만 하고, `turn: 기획`일 때만 답한다.
6. 작업이 decided되고 검증이 main에 머지하면 다음 번호로 넘어간다.
7. 014까지 끝나면 모든 담당자에게 작업 리스트 완료를 알리고, 관련 모니터링 해제를
   지시한다.
